# 0.10. Базовое ООП: классы, __init__, self

## Зачем это нужно

Начиная с модуля 4 ты будешь работать с Page Object Model — подходом, где каждая страница сайта описывается отдельным классом (`LoginPage`, `RegistrationPage` и т.п.). В модуле 3 API-клиент тоже будет классом. Если сейчас не разобраться, что такое класс, `__init__` и `self`, весь этот код превратится в набор непонятных символов. Цель этого урока — ровно наоборот: чтобы, открыв любой чужой класс, ты понимал, что происходит.

Материал написан специально под тот минимум ООП, который нужен, чтобы читать тестовый фреймворк. Здесь нет наследования интерфейсов, множественного наследования, метаклассов и прочих продвинутых тем — только то, что реально встретится в коде.

## Теория

### От словаря к классу

До сих пор мы хранили связанные данные либо в отдельных переменных, либо в словаре:

```python
user = {"username": "ivan", "age": 25}
```

У словаря есть неудобство: рядом с данными нет действий, которые к ним относятся. Хочешь проверить, совершеннолетний ли пользователь — пишешь отдельную функцию `is_adult(user)` где-то в стороне, и связь между данными и функцией видна только по договорённости, а не по коду.

**Класс** — это шаблон, который описывает и данные (**атрибуты**), и действия над ними (**методы**) вместе, в одном месте. **Объект** (или **экземпляр**) — это конкретная "вещь", созданная по этому шаблону:

```python
class TestUser:
    def __init__(self, username, age):
        self.username = username
        self.age = age

    def is_adult(self):
        return self.age >= 18


user = TestUser("ivan", 25)   # создали экземпляр класса
print(user.username)          # ivan — обращение к атрибуту
print(user.is_adult())        # True — вызов метода
```

По договорённости имена классов пишут в `CamelCase` (`TestUser`, `BasePage`), а не в `snake_case`, как переменные и функции — это сразу помогает отличить класс от обычной переменной при чтении чужого кода.

### __init__ — конструктор

`__init__` — специальный метод-**конструктор**, который автоматически вызывается в момент создания объекта (`TestUser("ivan", 25)`). Его задача — заполнить начальные атрибуты объекта. Имя с двумя подчёркиваниями с обеих сторон (`__init__`) — соглашение Python для "магических" методов со специальным поведением; сейчас достаточно запомнить именно этот один.

```python
class ApiEndpoint:
    def __init__(self, method, path):
        self.method = method
        self.path = path


endpoint = ApiEndpoint("GET", "/users")   # __init__ выполнился автоматически при создании
print(endpoint.method, endpoint.path)      # GET /users
```

Если `__init__` не объявить вообще, объект всё равно можно создать — просто у него не будет собственных атрибутов, заданных при создании.

### self — ссылка на текущий объект

`self` — первый параметр любого метода класса, через который метод обращается к атрибутам *этого конкретного* объекта. Когда ты пишешь `user.is_adult()`, Python сам подставляет `user` в качестве `self` — тебе не нужно передавать его вручную при вызове. Но при *объявлении* метода `self` нужно прописывать явно первым параметром всегда — это не опция, а обязательное правило синтаксиса:

```python
def is_adult(self):       # self — обязателен при объявлении
    return self.age >= 18

user.is_adult()            # а при вызове self не передаём — он подставится сам
```

Внутри `__init__` строчка `self.username = username` создаёт атрибут `username` именно у *этого* объекта. Если создать два объекта — у каждого будут свои независимые значения атрибутов:

```python
user1 = TestUser("ivan", 25)
user2 = TestUser("olga", 17)
print(user1.is_adult())   # True
print(user2.is_adult())   # False — те же методы, но своё состояние
```

### Методы, вызывающие другие методы того же объекта

Один метод объекта может свободно вызывать другой метод того же объекта — через `self`. Это обычное дело в реальном коде: один метод собирает результат из более мелких "строительных блоков":

```python
class TestUser:
    def __init__(self, username, age):
        self.username = username
        self.age = age

    def is_adult(self):
        return self.age >= 18

    def describe(self):
        status = "adult" if self.is_adult() else "minor"
        return f"{self.username} ({status})"


user = TestUser("ivan", 25)
print(user.describe())   # ivan (adult)
```

`describe()` не дублирует логику из `is_adult()`, а переиспользует её через `self.is_adult()`. Ты будешь часто встречать этот приём в Page Object-классах модуля 4: например, метод, который проверяет, что вся форма видна, обычно просто вызывает несколько более мелких проверок по очереди.

### Чем это лучше словаря

В словаре ничего не мешает случайно записать ключ с опечаткой (`user["usrname"]`) — ошибку заметишь не сразу. У класса опечатка в имени атрибута (`user.usrname`) обычно сразу видна в среде разработки. Но главное — методы объекта живут рядом с данными и явно показывают, какие действия для этих данных предусмотрены: открыть `BasePage` и увидеть его методы — куда понятнее, чем гадать, какие функции "где-то" работают с конкретным словарём.

## Пример

Собственный класс для представления ответа API — то, с чем ты будешь работать в модуле 3, но уже на своих данных, без реальных запросов:

```python
class ApiResponse:
    def __init__(self, status_code, body):
        self.status_code = status_code
        self.body = body

    def is_success(self):
        return 200 <= self.status_code < 300

    def get_field(self, field_name):
        return self.body.get(field_name)


response = ApiResponse(200, {"id": 1, "username": "ivan"})
print(response.is_success())            # True
print(response.get_field("username"))   # ivan

error_response = ApiResponse(404, {"error": "not found"})
print(error_response.is_success())      # False
```

## Частые ошибки

- Забыть `self` первым параметром в объявлении метода — получишь `TypeError: takes 0 positional arguments but 1 was given` при вызове (Python сам подставляет объект первым аргументом, а метод его "не ждёт").
- Обратиться к атрибуту без `self.` внутри метода (`username = username` вместо `self.username = username`) — атрибут не создастся, а внутри `__init__` просто исчезнет параметр в никуда.
- Спутать класс (шаблон, `TestUser`) с объектом (конкретный экземпляр, `user`) — методы вызываются на объекте, а не на классе.
- Хранить общие для всех объектов данные не в `__init__` (через `self.`), а прямо в теле класса — тогда это будет один общий атрибут на все экземпляры сразу, а не у каждого свой (эта тонкость подробно разбирается уже за рамками этого курса, но полезно знать, что разница есть).

## Мини-задания

1. **Разминка.** Напиши класс `TestUser` в точности как в теории (`__init__` с `username` и `age`, метод `is_adult()`). Создай один объект с другими данными, чем в примере, и выведи его `username` и результат `is_adult()`.
2. **Основное.** Напиши класс `ApiResponse` (как в примере) и добавь ему метод `has_error()`, который возвращает `True`, если в `self.body` есть ключ `"error"`. Создай два объекта: один — успешный ответ с данными, второй — ответ с ошибкой, и проверь оба метода на них.
3. **Ближе к практике.** Напиши класс `LoginForm` с `__init__(self, username, password)`, сохраняющий оба значения в атрибуты. Добавь метод `is_valid()`, возвращающий `True`, если и `username`, и `password` — непустые строки. Добавь метод `describe()`, который вызывает `self.is_valid()` и возвращает `"valid login"` или `"invalid login"` — так же, как в Page Object один метод объекта часто использует другой метод того же объекта (см. `boilerplate/pages/registration_page.py`, где методы работают с атрибутами, заданными в `__init__`).
4. **Со звёздочкой.** В "Частых ошибках" упомянуто, что данные, объявленные прямо в теле класса (а не через `self.` в `__init__`), становятся одним общим атрибутом на все объекты сразу. Напиши **правильную** версию класса `TestRun` с `__init__(self)`, где `self.results` — новый пустой список для каждого объекта, и методом `add_result(name)`, добавляющим `name` в `self.results`. Создай два объекта `TestRun`, добавь в каждый разные результаты и убедись, что их списки `results` не совпадают и не влияют друг на друга.
