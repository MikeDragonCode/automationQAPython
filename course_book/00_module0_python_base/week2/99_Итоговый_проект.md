# 0.15. Итоговый проект модуля — скрипт-парсер публичного API

## Зачем это нужно

Это первая проверка, что синтаксис Python реально усвоен, а не просто "пройден по конспекту". Никакого pytest и никаких фреймворков здесь ещё нет — это придёт в модуле 1. Сейчас важно ровно одно: написать самостоятельный рабочий скрипт от начала до конца, который берёт данные снаружи (из интернета), а не только из захардкоженных в коде списков, и что-то осмысленное с ними делает. Это ровно то, чем ежедневно занимается automation engineer при подготовке тестовых данных или разборе логов ответа API — только пока без тестового фреймворка вокруг.

## Что нужно сделать

Напиши скрипт `final_project.py`, который:

1. Обращается к публичному API без ключей и токенов. Рекомендуемый вариант — [JSONPlaceholder](https://jsonplaceholder.typicode.com/), например к эндпоинту `https://jsonplaceholder.typicode.com/todos` (список задач с полями `userId`, `id`, `title`, `completed`). Подойдёт и любой другой публичный открытый API без авторизации, если он отдаёт JSON — например что-то из каталога [publicapis.org](https://publicapis.org/).
2. Делает HTTP-запрос модулем `urllib.request` из стандартной библиотеки (ничего дополнительно устанавливать не нужно) **или** модулем `requests`, если он у тебя уже установлен и ты хочешь попробовать. Для `urllib` это выглядит примерно так:

   ```python
   import json
   import urllib.request

   with urllib.request.urlopen("https://jsonplaceholder.typicode.com/todos") as response:
       raw_data = response.read()

   todos = json.loads(raw_data)
   ```

3. Разбирает полученный JSON в обычные Python-объекты (список словарей) — используя `json.loads()` (для `urllib`) или `.json()` (для `requests`).
4. Выполняет над данными хотя бы одну содержательную обработку — не просто печатает всё подряд. Например (выбери один вариант или придумай свой в том же духе):
   - посчитать количество выполненных (`completed: true`) и невыполненных задач по каждому `userId`;
   - отфильтровать и оставить только задачи одного конкретного пользователя;
   - найти пользователя с наибольшим числом выполненных задач.
5. Сохраняет результат обработки (не исходные "сырые" данные, а именно то, что получилось после обработки) в локальный файл `result.json` через `json.dump()`, с `ensure_ascii=False` и `indent=2`.
6. Также печатает короткую человекочитаемую сводку в консоль (2–5 строк).
7. Оборачивает сетевой запрос в `try/except`, чтобы при отсутствии интернета или ошибке сервера скрипт не падал с длинным traceback, а печатал понятное сообщение и корректно завершался.

## Ограничения

- Никакого `pytest`, `unittest` и вообще тестовых фреймворков — они будут в модуле 1. Это обычный Python-скрипт, запускаемый как `python final_project.py`.
- Никаких API с ключами/токенами/регистрацией — только полностью открытые.
- Используй минимум 2 собственные функции (`def`) — весь код одним куском без единой функции не принимается.
- Код должен реально запускаться и завершаться без необработанных исключений (кроме случая намеренной проверки отсутствия сети — там должно быть корректное сообщение, а не traceback).

## Критерии "готово"

- [ ] Скрипт запускается командой `python final_project.py` и не падает.
- [ ] Делает реальный HTTP GET-запрос к публичному API (`urllib.request` или `requests`).
- [ ] Полученный ответ распарсен в Python-объекты через `json` (не руками через `.split()` и подобное).
- [ ] Есть минимум одна агрегация/фильтрация данных (не просто вывод "как есть").
- [ ] Результат обработки сохранён в `result.json` в текущей папке — с отступами и читаемой кириллицей, если она есть.
- [ ] В консоль выводится краткая сводка результата.
- [ ] Сетевая ошибка (например, при выключенном интернете) обрабатывается через `try/except` и не приводит к падению с traceback.
- [ ] В коде есть минимум 2 функции с понятными именами и docstring или комментарием, объясняющим, что функция делает.

## Подсказка по структуре (не обязательна к дословному повторению)

```python
import json
import urllib.request
import urllib.error


def fetch_todos(url):
    """Делает GET-запрос и возвращает список словарей из JSON-ответа."""
    with urllib.request.urlopen(url, timeout=10) as response:
        raw_data = response.read()
    return json.loads(raw_data)


def summarize_by_user(todos):
    """Считает количество выполненных и невыполненных задач по каждому userId."""
    summary = {}
    for todo in todos:
        user_id = todo["userId"]
        summary.setdefault(user_id, {"completed": 0, "not_completed": 0})
        key = "completed" if todo["completed"] else "not_completed"
        summary[user_id][key] += 1
    return summary


def main():
    url = "https://jsonplaceholder.typicode.com/todos"

    try:
        todos = fetch_todos(url)
    except (urllib.error.URLError, TimeoutError) as error:
        print(f"Не удалось получить данные: {error}")
        return

    summary = summarize_by_user(todos)

    with open("result.json", "w", encoding="utf-8") as file:
        json.dump(summary, file, ensure_ascii=False, indent=2)

    print(f"Обработано пользователей: {len(summary)}")
    for user_id, stats in summary.items():
        print(f"User {user_id}: completed={stats['completed']}, not_completed={stats['not_completed']}")


if __name__ == "__main__":
    main()
```

Сдавай сам файл `final_project.py` (в модулях 0–1 домашки сдаются как файлы, PR в общий репозиторий начнётся с модуля 2). Приложи также получившийся `result.json`, чтобы было видно результат реального запуска.
