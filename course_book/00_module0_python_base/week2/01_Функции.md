# 0.8. Функции: def, return, аргументы

## Зачем это нужно

Любой тестовый фреймворк построен вокруг функций: сами тесты — это функции, вспомогательные шаги ("залогиниться", "создать тестового пользователя") — тоже функции. Не научившись выделять повторяющийся код в функцию, ты будешь копировать одни и те же пять строк в каждый тест — а это первое, за что бракуют код-ревью.

## Теория

Функция объявляется ключевым словом `def`, вызывается — именем со скобками:

```python
def send_request():
    print("sending request...")

send_request()   # вызов — без скобок это была бы просто ссылка на функцию, не вызов
```

Значения внутри скобок при объявлении называются **параметрами**, а то, что передаётся при вызове — **аргументами**. Порядок важен: первому параметру соответствует первый аргумент и так далее (это называется **позиционными** аргументами).

```python
def build_url(host, path):
    return f"{host}/{path}"

build_url("https://api.example.com", "users")
```

### return

Оператор `return` завершает выполнение функции и возвращает значение вызывающему коду. Без `return` функция всегда возвращает `None`. Как только выполнен `return`, весь код после него в этой же ветке уже не выполняется:

```python
def get_status_label(code):
    if 200 <= code < 300:
        return "success"
    return "error"
```

Вернуть можно сразу несколько значений — на самом деле это упаковка в кортеж:

```python
def get_min_max(numbers):
    return min(numbers), max(numbers)

low, high = get_min_max([5, 2, 9, 1])
```

### Именованные аргументы и значения по умолчанию

Аргументы можно передавать не только по позиции, но и по имени — тогда порядок неважен:

```python
build_url(path="users", host="https://api.example.com")
```

Параметру можно задать значение по умолчанию — тогда при вызове его можно не указывать:

```python
def get_users(base_url, page=1, per_page=20):
    return f"{base_url}/users?page={page}&per_page={per_page}"

get_users("https://api.example.com")               # page и per_page возьмутся по умолчанию
get_users("https://api.example.com", per_page=50)   # меняем только один параметр
```

**Важная ловушка**: никогда не используй изменяемый объект (список, словарь) как значение по умолчанию — он создаётся один раз при объявлении функции и переиспользуется между всеми вызовами:

```python
def add_item(item, items=[]):   # плохо!
    items.append(item)
    return items

add_item(1)   # [1]
add_item(2)   # [1, 2] — а не [2], как можно было ожидать!
```

Правильный способ — использовать `None` как значение по умолчанию и создавать новый объект внутри функции:

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items
```

### Область видимости

Переменная, созданная внутри функции, — **локальная**: она не существует за пределами функции. Функция при этом видит переменные, объявленные снаружи (глобальные), но не может напрямую их *изменить* — присваивание внутри функции создаст новую локальную переменную с тем же именем. Если действительно нужно изменить глобальную переменную из функции, используется ключевое слово `global` — но на практике в тестовом коде такая необходимость возникает редко и обычно говорит о том, что стоит пересмотреть архитектуру (передавать значение через аргумент и возврат, а не через глобальное состояние).

```python
counter = 0

def increment_broken():
    counter = counter + 1   # UnboundLocalError: counter — локальная, но ещё не создана
```

Эта функция упадёт с ошибкой, а не молча изменит глобальный `counter`: Python видит присваивание `counter = ...` внутри функции и сразу решает, что `counter` здесь — локальная переменная на всём протяжении тела функции, значит справа от `=` она ещё не существует.

### Аннотации типов (type hints)

Python не требует указывать типы параметров и возвращаемого значения — код работает и без этого. Но в реальном тестовом коде (в том числе в `boilerplate/`, с которым ты будешь работать в модуле 4) типы почти всегда аннотированы — это подсказка для человека и для IDE, а не проверка, которую выполняет сам язык:

```python
def build_url(host: str, path: str) -> str:
    return f"{host}/{path}"
```

`host: str` и `path: str` — типы параметров, `-> str` перед двоеточием — тип возвращаемого значения. Python не остановит выполнение, если ты всё-таки передашь число вместо строки — аннотации ни на что не влияют во время выполнения, это чистая документация. Вот метод из настоящего файла `boilerplate/pages/base_page.py`, который ты увидишь в модуле 4:

```python
def open(self, url: str) -> None:
    self.page.goto(url)
```

`-> None` означает, что метод ничего не возвращает — частый случай для методов, которые выполняют действие (открыть страницу, кликнуть), а не вычисляют значение. Читать чужой код становится сильно проще, когда сигнатура функции уже сама по себе объясняет, что на вход и что на выход — привыкай к этому формату уже сейчас, даже если сам пока не всегда будешь его писать.

## Пример

```python
def calculate_discounted_price(price, discount_percent=10):
    return round(price * (100 - discount_percent) / 100, 2)


print(calculate_discounted_price(1999.99))          # скидка по умолчанию — 10%
print(calculate_discounted_price(1999.99, 25))      # позиционный аргумент
print(calculate_discounted_price(price=500, discount_percent=0))  # именованные
```

## Частые ошибки

- Забыть `return` и удивляться, почему результат функции — `None`.
- Изменяемое значение по умолчанию (`def f(items=[])`) — данные "утекают" между вызовами.
- Путать параметр (в объявлении) и аргумент (при вызове) в разговоре с коллегами — мелочь, но профессиональная лексика важна.
- Пытаться менять глобальную переменную внутри функции без `global` и не понимать, почему изменение "не сохраняется" снаружи.

## Мини-задания

1. **Разминка.** Напиши функцию `multiply(a, b)`, которая возвращает произведение `a` и `b`. Вызови её один раз с позиционными аргументами (`multiply(3, 4)`) и один раз с именованными в обратном порядке (`multiply(b=5, a=2)`), убедись, что оба вызова дают правильный результат.
2. **Основное.** Напиши функцию `format_test_report(test_name, passed, duration_ms=0)`, которая возвращает строку вида `"[PASSED] test_login (120 ms)"` или `"[FAILED] test_login (120 ms)"` в зависимости от значения `passed`. Параметр `duration_ms` должен иметь значение по умолчанию `0`. Вызови функцию три раза с разными комбинациями позиционных и именованных аргументов.
3. **Ближе к практике.** Напиши функцию `build_endpoint(base_url: str, path: str, page: int = 1) -> str`, которая по аналогии с реальным кодом (с аннотациями типов, как в `boilerplate/pages/base_page.py`) собирает URL вида `"https://api.example.com/users?page=1"`. Значение `page` по умолчанию — `1`. Проверь функцию с параметром по умолчанию, с позиционным `page` и с именованным `page`, переданным не третьим по счёту, а первым.
4. **Со звёздочкой.** Напиши функцию `add_result(item, results=None)`, которая добавляет `item` в список `results` и возвращает его — но так, чтобы **не** повторить ловушку с изменяемым значением по умолчанию из "Частых ошибок": при вызовах без явного `results` каждый вызов должен получать свой отдельный новый список, а не один общий, разделяемый между всеми вызовами. Проверь это, вызвав функцию дважды подряд без аргумента `results` и убедившись, что результаты не смешались.
