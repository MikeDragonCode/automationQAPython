# 0.11. Наследование

## Зачем это нужно

В Page Object Model у всех страниц сайта есть что-то общее (например, объект браузерной страницы, метод перехода по URL), но у каждой страницы — свои уникальные элементы и действия. Дублировать общий код в каждом классе — плохая практика (тот же принцип DRY, что и с функциями). Наследование позволяет описать общее один раз в "базовом" классе, а в каждом конкретном классе — дописать только то, что отличается. Именно так устроен `boilerplate/pages/`, с которым ты будешь работать с модуля 4.

Как и предыдущий урок, этот материал написан отдельно для курса — в исходном Stepik-курсе темы наследования нет вообще.

## Теория

Класс может **наследоваться** от другого класса — тогда он автоматически получает все его атрибуты и методы, и может добавить свои или переопределить существующие:

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def make_sound(self):
        return "..."


class Dog(Animal):          # Dog наследуется от Animal
    def make_sound(self):    # переопределяем метод
        return "Woof!"


rex = Dog("Rex")
print(rex.name)          # Rex — атрибут получен от Animal, ничего лишний раз не писали
print(rex.make_sound())  # Woof! — а этот метод у Dog свой
```

`class Dog(Animal):` — в скобках после имени класса указывается родительский класс (**базовый**, или **родительский**). `Dog` — **дочерний** класс (или **наследник**). Дочерний класс автоматически "видит" все методы родителя, если не определит собственный метод с тем же именем — тогда сработает именно его, дочерний, вариант (это называется **переопределением метода**).

### super() — обращение к родителю

Если у родителя есть `__init__` с полезной логикой, а у дочернего класса появляются дополнительные атрибуты — не нужно копировать код родительского `__init__`. Вместо этого дочерний класс вызывает родительский конструктор через `super()`:

```python
class Animal:
    def __init__(self, name):
        self.name = name


class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)   # вызываем __init__ родителя — он заполнит self.name
        self.breed = breed        # а это — уже своё, новое поле


rex = Dog("Rex", "Labrador")
print(rex.name, rex.breed)   # Rex Labrador
```

`super().__init__(name)` — эквивалент "выполни код родительского `__init__` для этого же объекта". Без этой строчки атрибут `self.name` у `Dog` вообще не появился бы — пришлось бы дублировать `self.name = name` вручную, а это как раз то дублирование, которого наследование призвано избежать.

### Зачем это в тестовом коде

Общий паттерн: `BasePage` хранит то, что нужно любой странице (сама страница браузера, метод открытия по URL), а каждая конкретная страница (`RegistrationPage`, `LoginPage`, `DashboardPage`) наследуется от него и добавляет свои локаторы элементов и свои действия.

## Пример: код из `boilerplate/`, который ты скоро будешь читать (и писать)

Ниже — два реальных файла из `boilerplate/pages/` этого курса. Их код использует Playwright, с которым мы познакомимся только в модуле 4 — но структурно это ровно то же наследование, что и в примере с `Animal`/`Dog` выше. Не пытайся понять здесь, что делает Playwright — смотри только на связку класс/наследование/`super()`.

`boilerplate/pages/base_page.py`:

```python
from playwright.sync_api import Page, expect


class BasePage:
    """
    Общая функциональность для всех страниц приложения: хранение объекта page,
    открытие страницы по URL, проверка текущего адреса.
    Конкретные страницы (RegistrationPage, DashboardPage, ...) наследуются от него.
    """

    def __init__(self, page: Page):
        self.page = page

    def open(self, url: str) -> None:
        self.page.goto(url)

    def check_current_url(self, expected_url: str) -> None:
        expect(self.page).to_have_url(expected_url)
```

`boilerplate/pages/registration_page.py`:

```python
from playwright.sync_api import Page, expect

from pages.base_page import BasePage


class RegistrationPage(BasePage):
    URL = "https://nikita-filonov.github.io/qa-automation-engineer-ui-course/#/auth/registration"

    def __init__(self, page: Page):
        super().__init__(page)

        self.email_input = page.locator("[data-testid='registration-form-email-input'] input")
        self.username_input = page.locator("[data-testid='registration-form-username-input'] input")
        self.password_input = page.locator("[data-testid='registration-form-password-input'] input")
        self.registration_button = page.locator("[data-testid='registration-page-registration-button']")

    def open_page(self) -> None:
        super().open(self.URL)

    def fill_registration_form(self, email: str, username: str, password: str) -> None:
        self.email_input.fill(email)
        self.username_input.fill(username)
        self.password_input.fill(password)

    def click_registration_button(self) -> None:
        self.registration_button.click()

    def check_visible_registration_form(self) -> None:
        expect(self.email_input).to_be_visible()
        expect(self.username_input).to_be_visible()
        expect(self.password_input).to_be_visible()
        expect(self.registration_button).to_be_visible()
```

Теперь разложи это по тому, что ты уже знаешь:

- `class RegistrationPage(BasePage):` — `RegistrationPage` наследуется от `BasePage`, значит автоматически получает `self.page`, метод `open()` и метод `check_current_url()`.
- `super().__init__(page)` в `__init__` регистрационной страницы — вызывает конструктор `BasePage`, который сохраняет `self.page = page`. Без этой строчки объект `RegistrationPage` не имел бы атрибута `self.page`, которым пользуются локаторы ниже.
- После вызова `super().__init__()` класс добавляет **свои** атрибуты — `email_input`, `username_input` и т.д. Это ровно то же самое, что `self.breed = breed` после `super().__init__(name)` в примере с `Dog`.
- `def open_page(self): super().open(self.URL)` — переопределённый метод, который **не заменяет**, а **переиспользует** логику родителя: вызывает `open()` из `BasePage`, просто подставляя уже готовый `self.URL`. Это ещё один способ использовать `super()` — не только в `__init__`.
- `URL` — атрибут класса (не объекта): значение одно и то же для всех страниц регистрации, поэтому не нужно передавать его в `__init__`.

Если бы `RegistrationPage` не наследовалась от `BasePage`, пришлось бы в каждом классе страницы заново писать `self.page = page`, `open()` и `check_current_url()` — то самое дублирование кода, о котором шла речь ещё в уроке про функции.

## Частые ошибки

- Забыть вызвать `super().__init__(...)` в дочернем классе — тогда атрибуты родителя (`self.page` в примере выше) просто не появятся, и любой метод, который на них рассчитывает, упадёт с `AttributeError`.
- Переопределить метод с другой сигнатурой (другим набором параметров), чем в родителе, — вызывающий код, рассчитывающий на родительскую сигнатуру, сломается.
- Слишком глубокая цепочка наследования (класс от класса от класса от класса) — так же вредно для читаемости, как и слишком глубокая вложенность условий.
- Путать переопределение метода (одноимённый метод в дочернем классе) с добавлением нового метода — это разные вещи с разным эффектом.
