# 0.12. Модули и пакеты

## Зачем это нужно

`boilerplate/` — это не один файл, а десятки файлов, разложенных по папкам (`pages/`, позже `api/`, `tests/`). Чтобы код из одного файла мог использовать классы и функции из другого, нужен импорт. Именно поэтому в начале `registration_page.py` (см. прошлый урок) стоит строчка `from pages.base_page import BasePage` — без понимания модулей и пакетов эта строчка выглядит как магия.

## Теория

**Модуль** — это просто один `.py`-файл. Если в файле `mymodule.py` объявлена функция и переменная:

```python
# mymodule.py
GREETING = "hello"

def shout(text):
    return text.upper() + "!"
```

то из другого файла в том же каталоге их можно импортировать:

```python
import mymodule

print(mymodule.GREETING)
print(mymodule.shout("hi"))
```

Или, если нужны только конкретные имена — без обращения через точку:

```python
from mymodule import shout

print(shout("hi"))
```

Для длинных или часто встречающихся имён модулей используют псевдоним через `as` — так делают, например, стандартно для `pandas as pd` в аналитике; в тестовом коде это тоже иногда встречается для сокращения:

```python
import mymodule as mm
```

Стандартная библиотека Python — это набор готовых модулей, которые не нужно ничего доустанавливать: `math`, `random`, `json`, `datetime`, `os` и десятки других. Импортируются они точно так же, как свои модули: `import math`.

**Важно**: не используй `from module import *` (импорт вообще всего) — так легко случайно затереть чужое имя своим или своё чужим, и непонятно, откуда взялась та или иная функция при чтении кода. Явный импорт конкретных имён — лучшая практика.

### __name__ == "__main__"

У каждого модуля есть служебная переменная `__name__`. Если файл запускают напрямую (`python mymodule.py`), она равна `"__main__"`. Если файл импортируют из другого файла — она равна имени модуля. Эта проверка часто встречается в реальном коде, чтобы отделить "код, который выполняется только при прямом запуске" (например, ручной тест модуля) от того, что должно работать и при импорте:

```python
def main():
    print("Running as a script")

if __name__ == "__main__":
    main()
```

### Пакеты

**Пакет** — это каталог с модулями, который сам может импортироваться как единое целое. Таков `pages/` в `boilerplate/` — это пакет, а `base_page.py` и `registration_page.py` внутри него — модули этого пакета. Импорт из пакета выглядит как путь через точку:

```python
from pages.base_page import BasePage
```

Здесь `pages` — имя пакета (каталога), `base_page` — имя модуля (файла `base_page.py` внутри него), `BasePage` — класс, объявленный в этом модуле. Именно так устроена вторая строчка импорта в `registration_page.py`, который ты уже видел в прошлом уроке.

Раньше для того, чтобы Python воспринимал каталог как пакет, требовался пустой файл `__init__.py` внутри него. В современном Python (3.3+) это не обязательно, но такой файл всё ещё часто встречается в проектах — в том числе как место для настройки того, что именно "видно" при импорте всего пакета целиком.

## Пример

Структура из двух файлов в одном каталоге:

```
project/
├── formatters.py
└── main.py
```

`formatters.py`:

```python
def format_report(test_name, passed):
    status = "PASSED" if passed else "FAILED"
    return f"[{status}] {test_name}"
```

`main.py`:

```python
from formatters import format_report

print(format_report("test_login", True))
# [PASSED] test_login

if __name__ == "__main__":
    print("Script started directly")
```

А вот как это выглядит на уровне пакета — ровно структура `boilerplate/pages/`:

```
boilerplate/
└── pages/
    ├── base_page.py         # class BasePage
    └── registration_page.py  # class RegistrationPage(BasePage)
```

```python
# в любом другом файле проекта
from pages.base_page import BasePage
from pages.registration_page import RegistrationPage
```

## Частые ошибки

- `from module import *` — импортирует всё подряд, включая то, что может незаметно конфликтовать с уже существующими именами.
- Забыть, что модуль выполняется целиком в момент импорта — если в модуле "на верхнем уровне" (не внутри функции) написан код с побочными эффектами (например, `print(...)`), он выполнится при каждом импорте.
- Путать `import module` (обращение через `module.name`) и `from module import name` (обращение напрямую как `name`) — это разные способы, выбирай осознанно, а не смешивай хаотично.
- Циклический импорт (модуль А импортирует Б, а Б импортирует А) — приводит к трудноуловимым ошибкам; обычно решается пересмотром структуры кода.

## Мини-задание

Создай два файла в одной папке: `calculators.py` с функцией `calculate_discount(price, percent)` (возвращает цену со скидкой) и `main.py`, который импортирует эту функцию через `from calculators import calculate_discount` и печатает результат для пары значений. Добавь в `main.py` проверку `if __name__ == "__main__":` вокруг вызова.
