# 0.14. Генераторы и полезные функции: map, filter, zip, sorted

## Зачем это нужно

Обработка списка ответов API, сравнение двух наборов тестовых данных, сортировка результатов по времени выполнения — типичные задачи, для которых Python предлагает готовые компактные инструменты вместо ручных циклов. Эти функции повсеместно встречаются в чужом коде, и без них любой более-менее плотный кусок обработки данных будет выглядеть нечитаемым набором `for`-циклов.

## Теория

### map() — применить функцию к каждому элементу

```python
map(function, iterable)
```

Возвращает **итератор** (объект, который можно перебрать один раз), а не готовый список — поэтому результат часто оборачивают в `list()`:

```python
prices = ["10", "25", "99"]
prices_as_numbers = list(map(int, prices))
print(prices_as_numbers)   # [10, 25, 99]
```

Эквивалент через генератор списков (чаще выбирают его, если функция простая):

```python
prices_as_numbers = [int(p) for p in prices]
```

### filter() — отобрать элементы по условию

```python
filter(function, iterable)
```

Оставляет только те элементы, для которых `function` вернула `True`. Тоже возвращает итератор:

```python
numbers = [1, 2, 3, 4, 5, 6]
even = list(filter(lambda x: x % 2 == 0, numbers))
print(even)   # [2, 4, 6]
```

Эквивалент через генератор списков: `[x for x in numbers if x % 2 == 0]` — обе формы равноправны, выбор часто дело вкуса и читаемости.

### zip() — "сшить" несколько коллекций поэлементно

```python
names = ["ivan", "olga"]
ages = [25, 30]

for name, age in zip(names, ages):
    print(name, age)
# ivan 25
# olga 30
```

Останавливается на самой короткой из переданных коллекций. Полезно, когда данные приходят раздельными списками, а обрабатывать их нужно парами.

### sorted() с аргументом key

`sorted(iterable, key=..., reverse=...)` — уже знакомая функция, но с аргументом `key` она раскрывается по-настоящему: `key` — это функция, которая вычисляет "значение для сравнения" для каждого элемента, вместо сравнения элементов напрямую.

```python
users = [
    {"name": "Ivan", "age": 25},
    {"name": "Olga", "age": 19},
    {"name": "Petr", "age": 40},
]

by_age = sorted(users, key=lambda u: u["age"])
by_age_desc = sorted(users, key=lambda u: u["age"], reverse=True)
```

Без `key` Python не знает, как сравнивать два словаря между собой — `key` явно указывает, по какому полю сортировать.

### Генераторное выражение — вычисление "на лету"

Запись `(x for x in ...)` — синтаксически почти как генератор списков (`[x for x in ...]`), но в круглых скобках вместо квадратных. Разница принципиальная: генератор списков сразу строит весь список в памяти, а **генераторное выражение** ничего не строит заранее — оно отдаёт значения по одному, по запросу, экономя память на больших объёмах данных:

```python
squares = (x ** 2 for x in range(5))
print(squares)         # <generator object ...> — это ещё не список, а объект-генератор
print(list(squares))   # [0, 1, 4, 9, 16] — значения вычислились только сейчас, при обходе
```

Важная особенность генератора — он **одноразовый**: как только его прошли один раз (например, обернули в `list()` или скормили `sum()`), он считается исчерпанным, и повторный проход не даст ничего:

```python
squares = (x ** 2 for x in range(5))
print(list(squares))   # [0, 1, 4, 9, 16]
print(list(squares))   # [] — генератор уже пройден один раз, второй проход пустой
```

Если нужно пройтись по данным несколько раз — сохраняй результат в обычный список через `list(...)`, а не держи генератор.

### all(), any(), sum() с генераторным выражением

`all(iterable)` — `True`, если **все** элементы истинны; `any(iterable)` — `True`, если истинен **хотя бы один**; `sum(iterable)` — сумма всех элементов. Все три обычно применяют не к готовому списку, а прямо к генераторному выражению — так не нужно строить промежуточный список, который потом всё равно один раз обходится и выбрасывается:

```python
statuses = [200, 200, 200]
print(all(s == 200 for s in statuses))   # True — все запросы успешны

statuses_with_error = [200, 500, 200]
print(any(s >= 500 for s in statuses_with_error))   # True — хотя бы одна ошибка сервера

durations = [{"name": "t1", "duration_ms": 120}, {"name": "t2", "duration_ms": 45}]
total_duration = sum(r["duration_ms"] for r in durations)
print(total_duration)   # 165
```

Обрати внимание: генераторное выражение здесь передаётся как единственный аргумент функции без дополнительных скобок (`all(s == 200 for s in statuses)`, а не `all((s == 200 for s in statuses))`) — так тоже можно, Python разрешает опускать внешние скобки, когда генератор — единственный аргумент вызова.

## Пример

Типичная обработка списка ответов API — то, чем ты будешь заниматься в итоговом проекте этого модуля:

```python
responses = [
    {"id": 1, "status": 200, "duration_ms": 120},
    {"id": 2, "status": 404, "duration_ms": 80},
    {"id": 3, "status": 200, "duration_ms": 340},
    {"id": 4, "status": 500, "duration_ms": 50},
]

# только успешные ответы
successful = list(filter(lambda r: r["status"] == 200, responses))
print(len(successful))   # 2

# длительности всех запросов
durations = list(map(lambda r: r["duration_ms"], responses))
print(durations)   # [120, 80, 340, 50]

# самый медленный запрос
slowest = sorted(responses, key=lambda r: r["duration_ms"], reverse=True)[0]
print(slowest["id"])   # 3

# есть ли хоть одна ошибка сервера (5xx)?
has_server_error = any(r["status"] >= 500 for r in responses)
print(has_server_error)   # True

# id и статус попарно
for id_, status in zip(map(lambda r: r["id"], responses), map(lambda r: r["status"], responses)):
    print(id_, status)
```

## Частые ошибки

- Забыть обернуть `map()`/`filter()` в `list()`, если нужен именно список, а не одноразовый итератор — попытка второй раз пройтись по нему циклом ничего не даст.
- Использовать `map`/`filter` там, где обычный генератор списков читается понятнее — выбор инструмента должен улучшать читаемость, а не демонстрировать знание синтаксиса.
- Забыть `key` в `sorted()` при сортировке списка словарей/объектов — Python не поймёт, как их сравнивать, и выбросит ошибку.
- Перепутать `all()` (все обязаны быть истинными) и `any()` (достаточно одного) — логическая ошибка, которую легко не заметить в собственном тесте.

## Мини-задания

1. **Разминка.** Дан список строк с числами: `["10", "25", "7"]`. Напиши функцию `to_int_list(strings)`, которая с помощью `map(int, strings)` и `list()` возвращает список этих же значений, но как целые числа.
2. **Основное.** Дан список словарей с результатами тестов: `[{"name": "t1", "duration_ms": 120}, {"name": "t2", "duration_ms": 45}, {"name": "t3", "duration_ms": 300}]`. С помощью `sorted()` и `key` получи список названий тестов, отсортированных по возрастанию длительности. С помощью `filter` и `lambda` оставь только тесты длиннее 100 мс. С помощью `any()` проверь, есть ли тест длиннее 250 мс.
3. **Ближе к практике.** Даны два списка одинаковой длины: `expected_statuses` и `actual_statuses` (ожидаемые и реально полученные коды ответов серии API-запросов). Напиши функцию `count_mismatches(expected, actual)`, которая с помощью `zip()` и генераторного выражения внутри `sum()` возвращает количество позиций, где значения не совпадают.
4. **Со звёздочкой.** Генераторы (и результат `map()`/`filter()`) можно пройти только один раз — если забыть обернуть их в `list()`, повторный проход не даст ничего, о чём предупреждают "Частые ошибки" этого урока. Напиши функцию `sum_twice(numbers)`, которая создаёт `doubled = map(lambda x: x * 2, numbers)`, считает сумму через `sum(doubled)`, а затем пытается посчитать сумму ещё раз тем же объектом `doubled`. Верни кортеж `(first_sum, second_sum)` и убедись, что `second_sum` действительно окажется равен `0` — так на практике видно, почему `map`-объект нужно сразу оборачивать в `list()`, если планируешь использовать его больше одного раза.
