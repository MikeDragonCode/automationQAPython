# 0.2. Числа, логика и сравнения

## Зачем это нужно

Проверка ожидаемого результата почти всегда сводится к сравнению чисел: код ответа сервера, время выполнения запроса, количество элементов в списке. А булева логика (`and`, `or`, `not`) — это то, из чего потом строятся условия и `assert`-ы в тестах.

## Теория

### Арифметические операторы

В Python два основных числовых типа: `int` (целые) и `float` (вещественные). Диапазон `int` практически не ограничен. Базовые арифметические операторы:

| Оператор | Смысл | Пример |
|---|---|---|
| `+` `-` `*` | сложение, вычитание, умножение | `2 + 3` |
| `/` | деление, **всегда** возвращает `float` | `8 / 2` → `4.0` |
| `//` | целочисленное деление (округление вниз) | `7 // 2` → `3` |
| `%` | остаток от деления | `10 % 3` → `1` |
| `**` | возведение в степень | `2 ** 10` → `1024` |

Приоритет операций такой же, как в математике: сначала `**`, потом `*`, `/`, `//`, `%`, потом `+`, `-`. Скобки меняют порядок вычислений. Есть один частый сюрприз: при делении отрицательных чисел `//` и `%` округляются "в сторону минус бесконечности", а не к нулю:

```python
print(-7 // 2)   # -4, а не -3
print(-7 % 2)    # 1, а не -1
```

Сокращённые операторы присваивания экономят строки: `i += 1` вместо `i = i + 1`, аналогично работают `-=`, `*=`, `/=`, `//=`.

### Округление: round() и модуль math

Функция `round()` округляет число, но не по школьным правилам, а по **банковскому округлению** — до ближайшего чётного при равном расстоянии:

```python
round(2.5)   # 2, а не 3
round(3.5)   # 4
```

У неё есть второй параметр — количество знаков после запятой:

```python
round(3.14159, 2)   # 3.14
```

Для более сложной математики есть модуль `math` из стандартной библиотеки:

```python
import math

math.ceil(4.1)    # 5 — округление вверх, до ближайшего целого
math.floor(4.9)   # 4 — округление вниз
math.sqrt(49)     # 7.0
math.pi           # 3.141592653589793
```

`math.ceil()` и `math.floor()` в отличие от `round()` не округляют к ближайшему, а всегда идут в одну сторону — это пригодится, например, чтобы посчитать, сколько целых "страниц" по 10 записей нужно на 23 результата: `math.ceil(23 / 10)` → `3`.

### Операторы сравнения

Тип `bool` — это `True`/`False`. Операторы сравнения:

```
<   >   <=   >=   ==   !=
```

```python
print(5 > 3)         # True
print(5 == 5.0)      # True — int и float сравниваются по значению
print(5 != "5")      # True — разные типы никогда не равны через ==
```

Обрати внимание: `==` — сравнение, `=` — присваивание, это разные операторы, и путаница между ними — классическая ошибка новичков.

### Логические операторы and, or, not

Составные условия строятся через `and`, `or`, `not`. Приоритет: `not` выполняется первым, затем `and`, и только потом `or`:

```python
print(True or False and False)   # True — сначала посчитается (False and False) = False, потом True or False
```

Python также позволяет "математическую" запись диапазона — она читается ближе к тому, как условие формулируют словами:

```python
y = 3
print(-2 <= y <= 5)   # True, эквивалент y >= -2 and y <= 5
```

### Приведение к bool: truthy и falsy

Функция `bool()` приводит любое значение к `True`/`False` по правилу "пустое — ложь": `0`, `0.0`, `""`, `[]`, `{}`, `None` — все дают `False`, всё остальное — `True`:

```python
print(bool(0))        # False
print(bool(""))       # False
print(bool([]))       # False
print(bool("0"))      # True — это непустая строка, а не число 0
```

Это правило часто используется неявно, например в условии `if some_list:` вместо `if len(some_list) > 0:` — оба варианта работают одинаково, но первый короче и считается более "питоничным". Полностью с условными операторами и `if` разберёмся в отдельном уроке, здесь важно только само правило truthy/falsy.

## Пример

```python
price = 1999.99
discount_percent = 15

discounted_price = round(price * (100 - discount_percent) / 100, 2)
print(discounted_price)  # 1699.99

expected_status = 200
actual_status = 201
is_success = 200 <= actual_status < 300
print(is_success)  # True — 201 тоже "успешный" HTTP-код

# сравнение вещественных чисел "в лоб" опасно из-за погрешности округления
result = 0.1 + 0.2
print(result == 0.3)                  # False, неожиданно!
print(abs(result - 0.3) < 1e-9)       # True — правильный способ сравнить float
```

## Частые ошибки

- Сравнивать вещественные числа через `==` — из-за особенностей хранения `float` в памяти `0.1 + 0.2 != 0.3`. Сравнивай через допустимую погрешность (`abs(a - b) < 1e-9`).
- Путать `/` и `//` — `/` всегда даёт `float`, даже `10 / 2` → `5.0`.
- Забывать про банковское округление в `round()` и удивляться, почему `round(0.5)` — это `0`, а не `1`.
- Писать `if flag == True:` вместо `if flag:` — работает, но не по стилю Python.

## Мини-задания

1. **Разминка.** Даны `a = 17` и `b = 5`. Посчитай и сохрани в переменные: `quotient` — результат целочисленного деления `a` на `b` (`//`), `remainder` — остаток от деления (`%`), `power` — `a` в степени `2` (`**`).
2. **Основное.** Дан заказ на сумму `price = 2450` рублей со скидкой `discount = 12` (в процентах). Посчитай итоговую сумму с округлением до копеек и сохрани в `total`. Затем для `actual_status = 304` сохрани в `is_ok_status` результат составного условия: код находится в диапазоне `[200; 299]` **или** равен `304`.
3. **Ближе к практике.** SLA на ответ сервера — `sla_ms = 500`. Фактическое время ответа — `actual_ms = 580`. Если запрос был повторным (`is_retry = True`), допускается превышение SLA на `20%`. Посчитай `effective_sla` (с учётом `is_retry`: обычный `sla_ms` или увеличенный на 20%) и `is_within_sla` — `True`/`False`, уложился ли `actual_ms` в `effective_sla`.
4. **Со звёздочкой.** Даны два вещественных числа, полученные как суммы: `total_a = 0.1 + 0.1 + 0.1` и `total_b = 0.3`. Сохрани в `naive_equal` результат их прямого сравнения через `==`, а в `safe_equal` — результат сравнения через допустимую погрешность `abs(total_a - total_b) < 1e-9`. Оба значения должны получиться разными — объясни себе, почему.
