# 0.5. Условия: if / elif / else, тернарный оператор

## Зачем это нужно

Любая проверка вида "если статус-код не 200 — тест упал" — это условный оператор. В будущем `assert` в pytest во многом заменит явные `if`, но логика ветвления в тестовом коде (подготовка данных, обработка разных сценариев ответа) остаётся ровно такой же.

## Теория

### Синтаксис if / elif / else

```python
if condition:
    # выполняется, если condition истинно
elif other_condition:
    # проверяется, если предыдущие условия ложны
else:
    # выполняется, если ни одно условие не сработало
```

`elif` можно повторять сколько угодно раз, `else` — не обязателен и может отсутствовать. Порядок строго такой: сначала `if`, потом (не обязательно) любое число `elif`, потом (не обязательно) один `else`. Условия проверяются по порядку сверху вниз, и выполняется только **первая** ветка, чьё условие оказалось истинным — даже если следующие условия тоже подошли бы:

```python
score = 85
if score >= 60:
    print("passed")
elif score >= 85:
    print("excellent")   # эта строка никогда не выполнится для score=85 — до неё уже сработал первый if
```

### Отступы — часть синтаксиса

Ключевое для Python — **отступы**. Блок кода, относящийся к `if`, определяется отступом (обычно 4 пробела), а не скобками `{}`, как в других языках. Это не просто стиль — это часть синтаксиса: неправильный отступ реально меняет логику программы, а не просто "выглядит некрасиво":

```python
status = 500
if status == 200:
    result = "ok"
    print("saving result")   # этот print относится к телу if — выполнится, только если status == 200

if status == 200:
    result = "ok"
print("saving result")       # а этот print уже ВНЕ if — выполнится всегда, независимо от status
```

Обе версии кода синтаксически корректны — Python не подскажет ошибку, просто выполнит не то, что ты имел в виду.

### Условие может быть любым выражением, приводимым к bool

В условии может быть любое выражение, приводимое к `bool` (см. правило truthy/falsy из прошлого урока), а не только явное сравнение:

```python
response_body = {"status": "ok"}   # непустой словарь — truthy

if response_body:      # сработает, если словарь/список не пустой
    print("есть данные")

errors = []             # пустой список — falsy
if not errors:
    print("ошибок нет")
```

### Вложенные условия

`if` можно вкладывать друг в друга — это нужно, когда вторая проверка имеет смысл, только если первая уже прошла:

```python
status_code = 200
response_time_ms = 950

if status_code == 200:
    if response_time_ms > 1000:
        print("OK, но медленно")
    else:
        print("OK")
else:
    print("FAIL")
```

Вложенность работает, но у неё есть цена: уже на третьем уровне такой код тяжело читать. Часто вложенность из двух `if` можно заменить одним условием через `and` (см. прошлый урок про логические операторы) — например, `if status_code == 200 and response_time_ms > 1000:` вместо двух вложенных `if`.

### Тернарный оператор

Компактная запись условия, которая **возвращает значение** (в отличие от обычного `if`, который сам по себе ничего не возвращает):

```python
status_label = "OK" if response.status_code == 200 else "FAIL"
```

Синтаксис: `<значение если True> if <условие> else <значение если False>`. Удобен для простых случаев — присвоить одно из двух значений. Для сложной логики с несколькими шагами тернарный оператор быстро становится нечитаемым, и в таких случаях лучше вернуться к обычному `if/elif/else`.

## Пример

```python
status_code = 404

if 200 <= status_code < 300:
    result = "success"
elif 400 <= status_code < 500:
    result = "client error"
elif 500 <= status_code < 600:
    result = "server error"
else:
    result = "unknown"

print(result)  # client error

# то же самое одним выражением для простого бинарного случая
is_ok = "yes" if status_code == 200 else "no"
print(is_ok)  # no
```

## Частые ошибки

- Неправильный отступ — код "уезжает" в блок `if`, хотя логически должен быть после него.
- Вложенность условий более 2–3 уровней — код становится нечитаемым; часто это признак того, что стоит пересмотреть структуру, а не самой логики.
- Попытка засунуть сложную многошаговую логику в тернарный оператор "для краткости" — читаемость страдает больше, чем экономится строк.
- Проверять число через `if value:` вместо явного `value is not None` — `0` тоже falsy, и валидное значение "ноль" незаметно превращается в "значения нет".

## Мини-задания

1. **Разминка.** Дано число `number = -7`. Напиши `if/elif/else`, определяющий знак числа, и сохрани результат в переменную `sign`: `"positive"`, `"negative"` или `"zero"`.
2. **Основное.** Напиши классификатор HTTP-статусов для `status_code = 404`: сохрани в `category` значение `"2xx success"`, `"3xx redirect"`, `"4xx client error"`, `"5xx server error"` или `"unknown"` для всего остального. Затем через тернарный оператор сохрани в `is_success` — `True`, если код успешный (в диапазоне `[200; 299]`), иначе `False`.
3. **Ближе к практике.** Дан результат запроса: `status_code = 200`, `response_time_ms = 1500`, `sla_ms = 1000`. Определи `verdict` по правилам: если `status_code` не `200` — `"FAIL"`; если `status_code == 200`, но `response_time_ms` больше `sla_ms` — `"SLOW"`; если `status_code == 200` и уложились в `sla_ms` — `"PASS"`.
4. **Со звёздочкой.** Дано `retry_count = 0` — количество оставшихся повторных попыток запроса. Сохрани в `wrong_check` результат проверки `if retry_count:` (то есть просто `bool(retry_count)`) — с точки зрения "есть ли ещё попытки" это неверно, потому что `0` — валидное число попыток, а не "значения нет". Сохрани в `correct_check` результат правильной явной проверки `retry_count > 0`. Оба должны получиться `False`, но объясни себе, почему для `retry_count = None` (когда информация о попытках вообще отсутствует) эти два способа дали бы разный результат.
