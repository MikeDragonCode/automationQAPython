# 0.4. Списки: индексы, срезы, методы, вложенные списки

## Зачем это нужно

Список тестовых пользователей, список ожидаемых элементов на странице, набор HTTP-кодов, которые нужно проверить в цикле — списки встречаются в тестовом коде постоянно. В отличие от строк, списки можно изменять "на месте", и это удобно, но и источник частых ошибок.

## Теория

### Список — изменяемый тип

Список задаётся квадратными скобками, элементы через запятую, может содержать данные разных типов:

```python
marks = [2, 3, 4, 3, 5, 2]
mixed = ["Москва", 1320, 5.8, True]
```

В отличие от строк, список — **изменяемый** тип: можно поменять значение по индексу, добавить или удалить элемент, и это не создаёт новый объект, а меняет существующий:

```python
marks[0] = 5
print(marks)   # [5, 3, 4, 3, 5, 2] — тот же список, изменённый на месте
```

### Индексы, срезы и копирование

Индексация и срезы работают так же, как у строк:

```python
marks[0]      # первый элемент
marks[-1]     # последний элемент
marks[1:3]    # элементы с индексом 1 и 2
marks[::-1]   # список в обратном порядке
```

Важное отличие от строк: полный срез `marks[:]` создаёт **новую копию** списка, а не ссылку на тот же объект (для кортежей `t[:]` вернёт тот же объект — это увидим в уроке 0.7). Метод `.copy()` делает то же самое, что и полный срез:

```python
original = [1, 2, 3]
alias = original          # НЕ копия — та же ссылка на тот же список
real_copy = original[:]   # копия — новый список с теми же значениями

alias.append(4)
real_copy.append(99)

print(original)    # [1, 2, 3, 4]  — изменился, потому что alias это тот же объект
print(real_copy)   # [1, 2, 3, 99] — на original не повлиял, это отдельный список
```

Обычное присваивание (`alias = original`) не копирует список — просто даёт второе имя тому же объекту, ровно как с любой переменной (см. урок 0.1). Для реальной копии нужен срез `[:]` или `.copy()`.

### Встроенные функции: len(), max(), min(), sum(), sorted()

Эти функции применимы к любой числовой коллекции и не меняют исходный список:

```python
response_times_ms = [120, 340, 95, 210, 800]

print(len(response_times_ms))   # 5 — количество элементов
print(min(response_times_ms))   # 95
print(max(response_times_ms))   # 800
print(sum(response_times_ms))   # 1565
print(sorted(response_times_ms))          # [95, 120, 210, 340, 800] — новый список
print(response_times_ms)                  # исходный не тронут: [120, 340, 95, 210, 800]
```

### Методы, которые меняют список "на месте"

| Метод | Что делает |
|---|---|
| `.append(x)` | добавить элемент в конец |
| `.insert(i, x)` | вставить элемент по индексу |
| `.remove(x)` | удалить первый элемент со значением `x` |
| `.pop(i=-1)` | удалить и вернуть элемент (по умолчанию последний) |
| `.sort(reverse=False)` | отсортировать список на месте |
| `.reverse()` | развернуть порядок элементов |

Эти методы обычно ничего не возвращают (точнее, возвращают `None`) — в отличие от `sorted()`, который возвращает новый список:

```python
tags = ["smoke", "regression"]
tags.append("api")
print(tags)   # ['smoke', 'regression', 'api']
```

Частая ошибка — писать `a = a.append(1)`: `append()` возвращает `None`, и после такой строчки `a` станет равен `None`, а не изменённому списку.

### Проверка вхождения и поиск позиции: in, .index()

Так же, как со строками, оператор `in` проверяет, есть ли значение в списке, а `.index()` возвращает позицию первого совпадения (и вызывает ошибку, если значения нет — как `.find()` и `.index()` у строк):

```python
codes = [200, 404, 200, 500]

print(404 in codes)        # True
print(codes.index(404))    # 1 — первое вхождение
print(999 in codes)        # False
```

### Вложенные списки

Список может содержать другие списки — так представляют таблицы и матрицы:

```python
users = [
    ["Ivan", 25, True],
    ["Olga", 30, False],
]
users[0]        # ['Ivan', 25, True]
users[0][1]     # 25
```

## Пример

```python
response_times_ms = [120, 340, 95, 210, 800, 150]

print(min(response_times_ms), max(response_times_ms))
# 95 800

average = sum(response_times_ms) / len(response_times_ms)
print(round(average, 1))
# 285.8

slow_requests = sorted(response_times_ms, reverse=True)[:3]
print(slow_requests)
# [800, 340, 210] — три самых медленных запроса

# добавляем новый результат, не трогая исходный список через sorted()
response_times_ms.append(500)
print(response_times_ms)
# [120, 340, 95, 210, 800, 150, 500]
```

## Частые ошибки

- Путать `.sort()` (меняет список, ничего не возвращает) и `sorted()` (возвращает новый список, исходный не меняет).
- Писать `a = a.append(x)` и терять список (получая `None`).
- Забывать, что `b = a` не копирует список — обе переменные ссылаются на один и тот же объект; для копии нужен срез `a[:]` или `a.copy()`.
- Путать номер элемента (считая с 1, "по-человечески") с индексом (считается с 0).

Посчитай количество успешных (`True`) в `passed` и провалившихся (`False`) в `failed`. Собери строку `summary` вида `"Passed: N, Failed: M"`. Отдельно получи срезом список с последними тремя результатами в `last_three`.
3. **Ближе к практике.** Дан список кодов ответа сервера `status_codes = [200, 200, 404, 200, 500, 200]`. Проверь через `in`, что код `500` присутствует в списке — сохрани в `has_server_error`. Найди позицию первого `404` через `.index()` — сохрани в `first_404_index`. Получи `sorted_codes` — отсортированную копию списка (`sorted()`), не трогая исходный `status_codes`, и убедись, что `status_codes` остался в исходном порядке.
4. **Со звёздочкой.** Дан список `original = [1, 2, 3]`. Заведи `buggy_copy = original` (обычное присваивание) и `real_copy = original.copy()` (настоящая копия). Добавь `99` в оба через `.append()`. Сохрани в `original_after` итоговое значение `original` — из-за `buggy_copy` оно тоже изменится, хотя менять `original` явно никто не просил. Объясни себе, почему `real_copy` на `original` не повлияла, а `buggy_copy` — повлияла.
