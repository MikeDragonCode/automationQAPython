# 4.12. Разбираем BasePage построчно

## Зачем это нужно

`BasePage` — это фундамент, от которого наследуются все страницы в `boilerplate/`, включая ту, которую ты добавишь в домашнем задании. Прежде чем писать новый Page Object, нужно точно понимать, что уже "достаётся бесплатно" через наследование, а что нужно реализовывать самому.

## Теория

Открой файл `boilerplate/pages/base_page.py` — весь его код уместился в 19 строк:

```python
from playwright.sync_api import Page, expect


class BasePage:
    """
    Общая функциональность для всех страниц приложения: хранение объекта page,
    открытие страницы по URL, проверка текущего адреса.
    Конкретные страницы (RegistrationPage, DashboardPage, ...) наследуются от него.
    """

    def __init__(self, page: Page):
        self.page = page

    def open(self, url: str) -> None:
        self.page.goto(url)

    def check_current_url(self, expected_url: str) -> None:
        expect(self.page).to_have_url(expected_url)
```

Разберём каждую часть.

### Импорты

```python
from playwright.sync_api import Page, expect
```

`Page` — тип объекта Playwright, представляющего вкладку браузера (тот самый `page`, с которым мы работали на неделе 9). Он импортируется здесь для аннотации типа в конструкторе — сам класс `Page` не создаётся, а только используется для подсказки, что именно ожидается на вход. `expect` — та же функция для проверок, которую мы разбирали в уроке 4.7.

### Конструктор

```python
def __init__(self, page: Page):
    self.page = page
```

Когда позже будет создаваться объект конкретной страницы (например, `RegistrationPage(page)`), внутрь передаётся объект Playwright `page`, полученный из фикстуры `pytest-playwright`. Конструктор `BasePage` сохраняет его в атрибуте `self.page`. После этого любой метод любой страницы, унаследованной от `BasePage`, может обращаться к браузеру через `self.page.goto(...)`, `self.page.locator(...)` и так далее.

Почему это важно понимать заранее: каждая новая страница, которую ты создашь, должна вызвать этот конструктор через `super().__init__(page)` — иначе `self.page` не появится, и все методы, которые на него полагаются, сломаются. Мы увидим это в следующем уроке на примере `RegistrationPage`.

### Метод `open`

```python
def open(self, url: str) -> None:
    self.page.goto(url)
```

Принимает URL и открывает его через Playwright. Метод сам по себе не делает ничего особенного — это обёртка над `page.goto(...)`. Ценность не в сложности реализации, а в том, что это единая точка, через которую любая страница проекта открывается по URL. Если понадобится, например, логировать каждое открытие страницы — это единственное место, которое нужно будет изменить.

### Метод `check_current_url`

```python
def check_current_url(self, expected_url: str) -> None:
    expect(self.page).to_have_url(expected_url)
```

Проверяет, что текущий URL страницы совпадает с ожидаемым. Обрати внимание: здесь используется `expect(self.page).to_have_url(...)`, а не `assert self.page.url == expected_url`. Как мы разобрали на уроке 4.7, `expect()` умеет ждать нужное состояние — если переход на страницу занимает долю секунды, `expect()` подождёт, а обычный `assert` мог бы сработать слишком рано и дать ложное падение теста.

## Пример

`BasePage` сам по себе не используется напрямую в тестах — он не описывает никакую конкретную страницу приложения. Его роль видна только через наследование:

```python
class RegistrationPage(BasePage):
    ...

class DashboardPage(BasePage):
    ...
```

Обе страницы автоматически получают `self.page`, `open()` и `check_current_url()`, не переписывая их заново. Это и есть смысл базового класса: общая функциональность реализована один раз, а не дублируется в каждой странице.

## Частые ошибки

- Пытаться сразу расширить `BasePage` большим количеством "универсальных" методов — в реальных проектах базовый класс страницы действительно может содержать больше возможностей (ожидания загрузки, работу с попапами, общие проверки), но в этом курсе он специально оставлен простым, чтобы не размывать саму идею наследования. Если для домашнего задания тебе не хватает какого-то общего метода — сначала подумай, действительно ли он общий для нескольких страниц, а не специфичен для одной.
- Забыть, что `open()` и `check_current_url()` уже существуют в `BasePage`, и продублировать их в новой странице вместо использования через `super()`.
- Менять сам `base_page.py` под задачи конкретной страницы — если новой странице нужно что-то своё, это должно жить в её собственном классе, а не в общем `BasePage` (иначе следующая правка "под одну страницу" начнёт ломать остальные).
