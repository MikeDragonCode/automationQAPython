# 4.9. Попапы, алерты и модальные окна

## Зачем это нужно

Рано или поздно в реальном проекте встретится: браузерное окно подтверждения ("Вы уверены, что хотите удалить?"), ссылка, открывающая новую вкладку, или модальное окно с формой поверх страницы. Каждый из этих случаев устроен по-своему, и важно понимать разницу, чтобы не пытаться, например, искать локатором браузерный `alert()` — он не является частью DOM-дерева страницы.

## Теория

Здесь стоит разделить три разных вещи, которые часто путают под общим словом "попап".

### 1. Нативные диалоги браузера: `alert`, `confirm`, `prompt`

Это встроенные диалоговые окна самого браузера — `window.alert(...)`, `window.confirm(...)`, `window.prompt(...)`, а также диалог подтверждения ухода со страницы (`beforeunload`). Они не являются HTML-элементами и не находятся в DOM, поэтому `page.locator(...)` их не увидит.

Playwright взаимодействует с ними через событие `dialog`:

```python
def handle_dialog(dialog):
    print(dialog.message)
    dialog.accept()

page.on("dialog", handle_dialog)
```

Важный момент поведения: если на странице появляется такой диалог, а обработчик `page.on("dialog", ...)` не зарегистрирован, Playwright автоматически закрывает диалог сам (аналог нажатия "Отмена"), чтобы тест не завис в ожидании. Если тебе нужно явно принять или отклонить диалог — регистрируй обработчик и внутри него вызывай `dialog.accept()` (можно передать текст для `prompt`) или `dialog.dismiss()`.

### 2. Новые вкладки и окна: `target="_blank"`, `window.open()`

Если клик по ссылке или кнопке открывает не текущую страницу, а новую вкладку, у тебя появляется новый объект `page`, за которым нужно проследить отдельно. Для этого Playwright предоставляет `expect_popup()`:

```python
with page.expect_popup() as popup_info:
    page.locator("a[target='_blank']").click()

new_page = popup_info.value
new_page.wait_for_load_state()
```

`expect_popup()` — это менеджер контекста, который ждёт появления новой вкладки в момент клика и возвращает её как отдельный объект `page`. Дальше с этим объектом работаем так же, как с обычной страницей: ищем локаторы, кликаем, проверяем.

### 3. Модальные окна внутри страницы (custom-модалки)

Это самый частый случай в современных SPA-приложениях (React, Vue и подобных) — визуально модальное окно выглядит как всплывающее поверх страницы, но технически это обычный `<div>` с определённым `role="dialog"` или собственным `data-testid`, который просто отрисован поверх остального контента через CSS. Такое окно — часть DOM-дерева, и никакой особой техники не нужно: находишь его как обычный элемент через `page.locator(...)` и работаешь с полями и кнопками внутри него так же, как с любой другой формой.

```python
modal = page.locator("[data-testid='confirm-delete-modal']")
expect(modal).to_be_visible()

modal.locator("button:has-text('Confirm')").click()
```

### Как отличить, с чем ты имеешь дело

Открой DevTools и посмотри на модальное окно во вкладке Elements. Если это HTML-элемент (`div`, `dialog` и т.п.) — это случай 3, работай через обычные локаторы. Если элемента в DOM нет, а окно всё равно появилось — скорее всего, это нативный `alert`/`confirm`/`prompt`, и нужен `page.on("dialog", ...)`.

### `dialog.type` — какой именно это диалог

Объект `dialog`, который Playwright передаёт в обработчик, несёт информацию не только про текст (`dialog.message`), но и про то, какого вида был диалог, — `dialog.type` (например, `"alert"`, `"confirm"`, `"prompt"`, `"beforeunload"`). Это полезно, когда один обработчик регистрируется на всю страницу, а разные элементы на ней вызывают диалоги разных видов, и реагировать на них нужно по-разному:

```python
def handle_dialog(dialog):
    if dialog.type == "confirm":
        dialog.accept()
    else:
        dialog.dismiss()

page.on("dialog", handle_dialog)
```

Обработчик регистрируется один раз и сработает на каждый диалог, который появится дальше на странице, — необязательно подписываться заново перед каждым отдельным диалогом.

### Не забываем про лишние вкладки

После работы с новой вкладкой, полученной через `expect_popup()`, её стоит закрыть, если она больше не нужна для теста, — так же, как закрывается обычный `page` или `browser`:

```python
new_page.close()
```

Для одного короткого учебного скрипта это не критично, а вот в наборе из десятков UI-тестов незакрытые вкладки постепенно накапливаются и расходуют память браузера.

## Пример

Гипотетический пример регистрации обработчика диалога перед действием, которое его вызывает:

```python
page.on("dialog", lambda dialog: dialog.accept())
page.locator("[data-testid='delete-account-button']").click()
```

Обработчик регистрируется один раз и будет автоматически обрабатывать любые диалоги, которые появятся на странице после этой строки.

## Частые ошибки

- Пытаться найти `alert()` через `page.locator(...)` — он не в DOM, так работать не будет.
- Забыть зарегистрировать `page.on("dialog", ...)` до клика, который вызывает диалог — обработчик должен быть подписан заранее, а не после того, как диалог уже появился.
- Принять кастомное модальное окно (обычный `div` с `data-testid`) за нативный диалог и пытаться работать с ним через `dialog.accept()` вместо обычного локатора.
- Регистрировать один обработчик диалогов без учёта `dialog.type` там, где разные элементы страницы вызывают диалоги разного вида, — обработчик, написанный в расчёте только на `alert`, может неправильно среагировать на `confirm` или `prompt`.

## Мини-задания

1. **Разминка.** Открой `https://the-internet.herokuapp.com/javascript_alerts` и кликни по кнопке "Click for JS Alert" **без** зарегистрированного `page.on("dialog", ...)`. По теории выше Playwright должен закрыть диалог сам — убедись, что скрипт не завис и не упал с ошибкой.

2. **Основное.** На той же странице зарегистрируй обработчик с `dialog.accept()` и кликни по кнопке "Click for JS Alert" ещё раз — проверь через `expect(page.locator("#result")).to_have_text("You successfully clicked an alert")`. Повтори для кнопки "Click for JS Confirm", но один раз прими диалог (`dialog.accept()`) и проверь `#result` на текст `"You clicked: Ok"`, а другой раз — отклони (`dialog.dismiss()`) и проверь `"You clicked: Cancel"`.

3. **Ближе к практике.** На той же странице есть третья кнопка — "Click for JS Prompt". Зарегистрируй обработчик, который вызывает `dialog.accept("твой текст")`, кликни по кнопке и проверь через `expect(page.locator("#result")).to_have_text(...)`, что введённый тобой текст действительно попал в результат.

4. **Со звёздочкой.** Напиши **один** обработчик диалогов, использующий `dialog.type`: для `"alert"` он вызывает `accept()`, для `"confirm"` — тоже `accept()`, а для `"prompt"` — `accept("test value")`. Зарегистрируй его один раз в начале скрипта и по очереди кликни по всем трём кнопкам на странице — проверь `#result` после каждого клика и убедись, что каждый диалог обработался правильной веткой одного и того же обработчика, без повторной регистрации.
