# 4.8. Работа с формами: fill, click, select, чекбоксы

## Зачем это нужно

Формы регистрации, логина, фильтров, настроек профиля, оформления заказа — это, пожалуй, самый частый объект UI-тестирования. До сих пор мы работали только с текстовыми полями и одной кнопкой. В реальных формах встречаются ещё выпадающие списки (`select`), чекбоксы (`checkbox`) и радиокнопки (`radio`) — с ними тоже нужно уметь работать, даже если в нашем учебном сценарии регистрации их нет.

## Теория

Playwright предоставляет отдельные методы под разные типы полей — это логично, ведь ввести текст в `input` и выбрать пункт в `select` физически разные действия для пользователя, и код должен их отражать.

### Текстовые поля: `.fill()`

Уже знакомый метод для однострочных (`input`) и многострочных (`textarea`) полей:

```python
page.locator("[data-testid='registration-form-email-input'] input").fill("user@example.com")
```

`.fill()` полностью заменяет содержимое поля — сначала очищает его, затем вставляет новое значение.

### Кнопки и клики: `.click()`

```python
page.locator("[data-testid='registration-page-registration-button']").click()
```

`.click()` подходит не только для кнопок `<button>`, но и для любых кликабельных элементов — ссылок, иконок, пунктов меню.

### Выпадающие списки: `.select_option()`

Для тега `<select>` в Playwright используется отдельный метод — `select_option()`. Он может принимать значение атрибута `value`, видимый текст варианта (`label`) или индекс:

```python
page.locator("select[name='country']").select_option(value="by")
```

Так работает выбор пункта в выпадающем списке из стандартного HTML-элемента `<select>`. Если на странице используется кастомный компонент выбора (например, стилизованный дропдаун из UI-библиотеки, где вместо `<select>` набор `<div>` и `<li>`), `select_option()` не подойдёт — там придётся кликать по элементу, который открывает список, а затем по нужному пункту как по обычному элементу через `.click()`. Какой вариант перед тобой — стандартный `<select>` или кастомный компонент — всегда можно понять через DevTools, посмотрев на реальные теги в разметке.

### Чекбоксы и радиокнопки: `.check()` / `.uncheck()`

Для `<input type="checkbox">` и `<input type="radio">` вместо клика используются методы `.check()` и `.uncheck()`:

```python
page.locator("input[name='remember_me']").check()
```

`.check()` установит чекбокс в отмеченное состояние, если он ещё не отмечен (если уже отмечен — ничего не сделает, что удобнее, чем обычный `.click()`, который просто переключил бы состояние). `.uncheck()` работает наоборот — снимает отметку.

Проверить состояние чекбокса можно через `expect()`:

```python
expect(page.locator("input[name='remember_me']")).to_be_checked()
```

### Радиокнопки в группе — только один вариант

Радиокнопки, объединённые одинаковым атрибутом `name`, образуют группу, из которой браузер позволяет выбрать только один вариант, — это обычное поведение HTML, а не что-то специфичное для Playwright. Если вызвать `.check()` сначала на одной радиокнопке группы, а затем на другой, в итоге останется отмеченной только последняя:

```python
page.locator("input[name='size'][value='small']").check()
page.locator("input[name='size'][value='large']").check()
# теперь отмечен только 'large' — 'small' автоматически снялся
```

Проверить, какой именно вариант отмечен, можно тем же `expect(...).to_be_checked()`, применённым к конкретной радиокнопке.

### Когда `.fill()` недостаточно: ввод посимвольно

`.fill()` устанавливает значение поля целиком и мгновенно — этого хватает для подавляющего большинства форм. Изредка встречаются поля, у которых JS-логика реагирует именно на события нажатия клавиш (например, поле с автоподсказками, обновляющееся по мере ввода каждого символа) — в таком случае `.fill()` может не вызвать нужную реакцию, потому что он не эмулирует реальную печать по одному символу. У Playwright для таких редких случаев есть отдельный способ вводить текст посимвольно. Если столкнёшься с полем, которое ведёт себя по-разному в зависимости от способа ввода, — это повод свериться с документацией Playwright за точным методом для используемой версии библиотеки; в большинстве повседневных задач обычного `.fill()` вполне достаточно.

### Ищем поле внутри конкретной формы

Если на странице несколько похожих полей в разных секциях (например, форма логина и форма подписки на рассылку — в обеих может быть `input[name='email']`), общий локатор `page.locator("input[name='email']")` найдёт сразу оба и упадёт с ошибкой неоднозначности (см. урок 4.6). Решение — сузить поиск: сначала найти контейнер нужной формы, а затем искать поле уже внутри него:

```python
login_form = page.locator("[data-testid='login-form']")
login_form.locator("input[name='email']").fill("user@example.com")
```

`.locator(...)`, вызванный на другом локаторе, ищет не по всей странице, а только внутри уже найденного элемента — это тот же принцип, что и обычный `page.locator(...)`, просто с более узкой областью поиска.

### Общий принцип

Все эти методы объединяет одно: сначала мы получаем локатор через `page.locator(...)`, а затем вызываем на нём метод, соответствующий типу элемента и нужному действию. Playwright сам разбирается, как физически "нажать" на элемент нужного типа — вам не нужно эмулировать конкретные события мыши или клавиатуры.

## Пример

Представим гипотетическую (не из нашего учебного приложения) форму с чекбоксом согласия и выбором страны:

```python
from playwright.sync_api import expect, sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)
    page = browser.new_page()

    page.goto("https://example.com/signup")

    page.locator("input[name='email']").fill("user@example.com")
    page.locator("select[name='country']").select_option(value="by")
    page.locator("input[name='agreement']").check()

    expect(page.locator("input[name='agreement']")).to_be_checked()

    page.locator("button[type='submit']").click()

    browser.close()
```

Обрати внимание: три разных типа полей — три разных метода (`fill`, `select_option`, `check`), но единый подход к поиску элемента через `page.locator(...)`.

## Частые ошибки

- Пытаться заполнить `<select>` через `.fill()` — это текстовый метод, для выпадающих списков он не подходит.
- Использовать `.click()` для чекбокса вместо `.check()`/`.uncheck()` — клик просто переключит текущее состояние, и если чекбокс уже был отмечен, тест случайно его снимет.
- Не учитывать, что визуально похожий на `<select>` компонент на самом деле собран из `<div>` — в таком случае `select_option()` не найдёт нужного элемента, потому что физически в разметке нет тега `<select>`.
- Пытаться "отметить" сразу несколько радиокнопок одной группы через `.check()` по очереди, рассчитывая, что отметятся обе, — в HTML-группе с одинаковым `name` в любой момент времени остаётся отмеченным только последний вызов.

## Мини-задания

1. **Разминка.** Открой в браузере `https://httpbin.org/forms/post`. Заполни только поле `custname` через `.fill()` своим именем и сразу проверь `expect(page.locator("input[name='custname']")).to_have_value(...)` — без чекбоксов, радиокнопок и без отправки формы.

2. **Основное.** На той же странице есть текстовое поле, радиокнопки и чекбоксы `topping` (`bacon`, `cheese`, `onion`, `mushroom`). По образцу скрипта из урока 4.6 напиши и запусти Playwright-скрипт: заполни поле `custname` через `.fill()`, отметь минимум два чекбокса из `topping` через `.check()`, проверь оба через `expect(...).to_be_checked()`, затем нажми кнопку отправки формы. После сабмита httpbin показывает страницу с тем, что было отправлено, — проверь на ней через `expect(page.locator("body")).to_contain_text(...)`, что твои данные (например, значение `custname`) действительно попали в отправленную форму.

3. **Ближе к практике.** Расширь скрипт из задания 2: дополнительно выбери один вариант из радиогруппы `size` (`small`/`medium`/`large`) через `.check()` и заполни поле `comments` через `.fill()`. После отправки формы проверь через `expect(page.locator("body")).to_contain_text(...)`, что и выбранный размер, и текст из `comments` попали в отправленные данные — так, как если бы ты проверял реальную многополевую форму заказа.

4. **Со звёздочкой.** Специально вызови `.check()` на двух разных вариантах радиогруппы `size` подряд — сначала `small`, затем `large`. Проверь через `expect(...).to_be_checked()` на локаторе `large` и `expect(...).not_to_be_checked()` на локаторе `small`, что в итоге отмеченным остался только последний вариант, а первый снялся автоматически, хотя ты его никак не "снимал" явно.
