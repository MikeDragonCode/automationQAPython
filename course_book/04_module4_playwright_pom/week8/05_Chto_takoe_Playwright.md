# 4.5. Что такое Playwright и зачем он нужен

## Зачем это нужно

Всё, что мы делали на этой неделе — HTML, DOM, DevTools, локаторы — было подготовкой к тому, чтобы понимать, с чем работает инструмент автоматизации. Теперь пора познакомиться с самим инструментом, который будет открывать браузер, находить элементы по нашим локаторам и выполнять действия. В этом курсе это [Playwright](https://playwright.dev/python/).

## Теория

**Playwright** — библиотека для автоматизации браузеров. Из Python-кода она умеет открывать страницы, находить элементы, вводить текст, кликать по кнопкам и проверять результат — то есть выполнять программно те же действия, которые обычно делает руками пользователь.

Например, пользователь открывает страницу регистрации, заполняет Email, Username, Password, нажимает Registration и видит Dashboard. Для Playwright это последовательность команд: открыть страницу → найти поле → ввести текст → найти кнопку → кликнуть → проверить результат. Именно такую последовательность мы соберём в следующих уроках.

### Как это устроено в общих чертах

Почти любой сценарий на Playwright строится по одной схеме:

1. Запустить браузер.
2. Открыть нужную страницу по URL.
3. Найти элементы через локаторы.
4. Выполнить действия (ввод текста, клики).
5. Проверить, что приложение отработало правильно.

Локатор поля Email мы уже знаем с прошлой недели:

```python
page.locator("[data-testid='registration-form-email-input'] input")
```

На прошлой неделе это была просто строка из урока про CSS-локаторы. Теперь она станет частью настоящего кода на Playwright.

### Какой браузер используем

Playwright умеет управлять разными браузерами, в курсе мы используем **Chromium** — движок, на котором построены Chrome, Edge, Brave и другие. Запуск браузера выглядит так:

```python
browser = p.chromium.launch(headless=False)
```

Пока не нужно разбирать эту строку целиком — в следующем уроке пройдёмся по каждой части. Важно понять главное: эта команда запускает браузер, которым дальше управляет Playwright.

### Что значит `headless=False`

Параметр `headless=False` означает, что браузер откроется в обычном видимом окне — ты своими глазами увидишь, как Playwright заполняет поля и нажимает кнопки. Это удобно на старте: не нужно гадать, что происходит внутри теста.

Когда тесты уже стабильны, их часто запускают в `headless`-режиме — без видимого окна. Это удобно для серверов и CI/CD (об этом — в модуле 6), но пока видимый браузер понятнее.

## Пример

Пока у нас нет кода — только идея. В следующем уроке (4.6) мы напишем первый рабочий скрипт, который запускает Chromium, открывает вкладку и закрывает браузер. Это и станет первым практическим применением всего, что мы обсудили.

## Частые ошибки

- Ожидать, что Playwright "видит" страницу так же, как человек — на самом деле он всегда работает через DOM и локаторы, а не через распознавание картинки.
- Путать Playwright с расширением браузера или инструментом для вёрстки — это библиотека для автоматизации, которая используется из Python-кода.
- Забывать, что headless-режим и видимый режим — это один и тот же Playwright, просто разный параметр запуска браузера.
