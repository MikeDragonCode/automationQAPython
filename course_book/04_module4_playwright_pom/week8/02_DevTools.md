# 4.2. DevTools: смотрим на страницу глазами браузера

## Зачем это нужно

Перед тем как писать локаторы, их нужно откуда-то взять. В реальной работе QA automation engineer не угадывает локаторы и не гуглит их — он открывает страницу, смотрит на её HTML-структуру через инструменты разработчика и сам решает, по какому атрибуту искать элемент. Это один из самых частых действий в повседневной работе, и его стоит довести до автоматизма.

## Теория

**DevTools** (Developer Tools) — встроенный набор инструментов браузера. Он есть в Chrome, Edge, Brave, Opera, Firefox — во всех современных браузерах, устроен похоже. Мы будем использовать DevTools в первую очередь для поиска элементов и построения локаторов, хотя инструмент умеет намного больше: смотреть сетевые запросы, ошибки JavaScript, стили CSS.

### Как открыть DevTools

- Клавиша **F12**.
- Горячие клавиши: `Ctrl + Shift + I` (Windows/Linux), `Cmd + Option + I` (macOS).
- Через контекстное меню: клик правой кнопкой по элементу страницы → **Inspect** (или **Просмотреть код**). Этот способ удобнее всего, когда нужно быстро найти конкретный элемент — DevTools сразу откроется на нужном месте дерева.

### Вкладка Elements

После открытия DevTools переходи на вкладку **Elements** — там показано DOM-дерево страницы, то есть та самая структура, о которой шла речь в прошлом уроке. Дерево может выглядеть громоздким — это нормально, не нужно понимать в нём каждую строку. Достаточно уметь находить нужные элементы и читать их атрибуты.

Полезная функция DevTools — подсветка при наведении: если навести курсор на узел в дереве, браузер подсветит соответствующий элемент на странице, и наоборот — клик правой кнопкой по элементу на странице и выбор Inspect откроет DevTools ровно на этом узле.

### Автоматический селектор — не панацея

DevTools умеет копировать готовый селектор элемента (клик правой кнопкой по узлу в дереве → **Copy** → **Copy selector** / **Copy XPath**). Это полезно для быстрого исследования страницы, но браузер не знает, какой из атрибутов элемента стабилен, а какой сгенерирован автоматически — поэтому такие селекторы часто получаются длинными, привязанными к структуре вёрстки и хрупкими. В следующем уроке разберём, как выбирать локатор осознанно, а не копировать первое, что предложил браузер.

## Пример

Открой страницу регистрации учебного приложения: `https://nikita-filonov.github.io/qa-automation-engineer-ui-course/#/auth/registration`.

1. Открой DevTools (F12).
2. Перейди на вкладку Elements.
3. Кликни правой кнопкой по полю Email на странице → Inspect.
4. Посмотри, какие атрибуты видны у элемента и у его родителя — обрати внимание на `data-testid`, `type`, `name`.

Повтори то же самое для поля Password и кнопки Registration.

## Частые ошибки

- Пытаться прочитать и понять весь HTML-документ целиком вместо того, чтобы искать конкретный элемент через Inspect.
- Слепо копировать `Copy selector` из DevTools в тест, не проверив, не завязан ли он на автогенерированный класс или порядковый номер `div`.
- Искать элемент во вкладке **Elements**, забыв, что там отображается текущее состояние DOM, которое может отличаться от исходного HTML-файла (JS мог изменить страницу после загрузки).

## Мини-задание

На странице регистрации учебного приложения (`.../#/auth/registration`) через Inspect найди все три поля формы (Email, Username, Password) и кнопку Registration. Для каждого элемента выпиши в блокнот (или заметку), какой атрибут выглядит наиболее стабильным для локатора — пока не пиши сам локатор, просто определи атрибут-кандидат.
