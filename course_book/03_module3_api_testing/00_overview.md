# Модуль 3. API-тестирование на requests (недели 6–7)

До этого момента ты тестировал либо чистые функции (модуль 1), либо разбирался с Git и общим репозиторием (модуль 2). Теперь — первый настоящий слой автотестов: API. Большая часть багов в реальных проектах ловится именно на уровне API — это быстрее, стабильнее и дешевле, чем гонять всё через UI.

Модуль устроен иначе, чем можно ожидать: ты не пишешь API-клиент с нуля. В `boilerplate/` уже есть рабочий, проверенный `APIClient`, `UsersClient` и тесты на них поверх публичного демо-API [jsonplaceholder.typicode.com](https://jsonplaceholder.typicode.com). Твоя задача — сначала построчно разобраться, как это устроено, а затем научиться **наслаивать** на эту структуру новые методы и тесты, как это происходит в любой реальной команде: никто не переписывает фреймворк заново под каждую задачу.

Источник материала — `stepik-api-testing-advanced` (главы 05–07). Источник построен на библиотеке `httpx`, наш курс — на `requests`; все примеры кода в модуле адаптированы под `requests`, а идея архитектуры (`APIClient` → специализированные клиенты → Pydantic-схемы) сохранена.

## Итог модуля

Студент открывает PR в общий репозиторий с 5–7 новыми API-тестами: новые методы `UsersClient` (например, `update_user_api`, `delete_user_api`) наследуются от `APIClient`, у запроса и ответа есть Pydantic-схемы, тесты используют фикстуру `users_client` и проверяют не только счастливый путь, но и ошибки (404, невалидные данные).
