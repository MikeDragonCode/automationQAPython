# 5.4. Настройка и генерация отчёта

## Зачем это нужно

`allure-pytest` умеет только собирать сырые данные. Чтобы увидеть красивый HTML-отчёт с деревом тестов, графиками и историей — нужен отдельный инструмент, Allure CLI, и команда, которая превратит JSON в страницы.

## Теория

Два инструмента, которые не стоит путать:

1. **`allure-pytest`** — Python-пакет, ставится через `pip install -r requirements.txt` (уже в зависимостях boilerplate). Он ничего не показывает сам — только пишет `*-result.json` в папку `--alluredir`.
2. **Allure CLI (`allure`)** — отдельная программа на Java, ставится один раз на машину (через `brew install allure` на macOS, `scoop install allure` на Windows, или вручную из архива с официального сайта). Именно она умеет превращать JSON в HTML.

Две полезные команды CLI:

- `allure serve allure-results` — генерирует отчёт во временную папку и сразу открывает его в браузере. Удобно для локальной разработки.
- `allure generate allure-results -o allure-report --clean` — генерирует статический HTML-отчёт в постоянную папку `allure-report/`. Именно так обычно делают в CI, чтобы потом отчёт можно было опубликовать как артефакт (см. модуль 6).

## Пример

Локальный цикл разработки:

```bash
pytest --alluredir=allure-results
allure serve allure-results
```

Цикл для CI (генерация в статику, без открытия браузера — на CI-раннере браузера и не будет):

```bash
pytest --alluredir=allure-results
allure generate allure-results -o allure-report --clean
```

В `.github/workflows/ci.yml` и `.gitlab-ci.yml` общего репозитория уже настроена загрузка `allure-results` как артефакта пайплайна (см. `upload-artifact` / `artifacts:` в этих файлах) — этого достаточно, чтобы результаты не терялись после завершения job'а. Полноценную публикацию сгенерированного HTML-отчёта (например, на GitHub Pages или во внешний Allure-сервис) курс намеренно не покрывает — это уже задача уровня "настройка инфраструктуры", а не работы автотестера.

## Частые ошибки

- Ставить `allure-pytest` и ждать, что команда `allure` уже доступна в терминале — это разные установки, `allure-pytest` не тянет за собой Java CLI.
- Коммитить `allure-results/` или `allure-report/` в git — это сгенерированные артефакты конкретного прогона, место им в `.gitignore` (уже сделано в boilerplate).
- Путать `--alluredir` (флаг pytest, куда писать сырые данные) и `-o` у `allure generate` (куда класть готовый HTML) — это два разных пути в двух разных командах.

## Частые ошибки при первом запуске

- `allure: command not found` — значит, CLI не установлен или не в `PATH`; `pip install allure-pytest` эту проблему не решает, это разные инструменты.
- Пустой отчёт — обычно означает, что `pytest` запускали без `--alluredir`, и в указанной папке просто нет файлов.

## Мини-задание

Установи Allure CLI (один раз на свою машину) и прогони полный локальный цикл: `pytest --alluredir=allure-results` → `allure serve allure-results`. Найди в открывшемся отчёте вкладку "Suites" и убедись, что видишь дерево `epic -> feature -> test` из своих тестов.
