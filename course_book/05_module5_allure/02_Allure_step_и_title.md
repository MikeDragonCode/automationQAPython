# 5.2. allure.step и allure.title

## Зачем это нужно

Название функции теста (`test_get_user`) и её докстринг — это то, что видит разработчик, читающий код. А человек, который просто смотрит отчёт после ночного прогона в CI, кода не открывает. Ему нужно человекочитаемое название сценария и пошаговая раскладка того, что происходило — именно это дают `allure.title` и `allure.step`.

## Теория

Три основных декоратора/контекст-менеджера, с которых стоит начать:

- **`@allure.title("...")`** — задаёт человекочитаемое название теста в отчёте вместо технического `test_get_user`.
- **`@allure.epic("...")` / `@allure.feature("...")`** — группируют тесты в отчёте по крупным разделам (например epic="API", feature="Users") — по ним строится дерево в интерфейсе Allure.
- **`with allure.step("..."):`** — оборачивает часть теста в именованный шаг. В отчёте шаги показываются как раскрывающийся список, и если тест упал — видно, на каком именно шаге.

Всё это уже используется в общем репозитории. Открой:

```
boilerplate/tests/api/test_users.py
boilerplate/tests/ui/test_registration.py
```

## Пример

Разбор реального теста из `boilerplate/tests/api/test_users.py`:

```python
@allure.epic("API")
@allure.feature("Users")
@pytest.mark.api
class TestUsers:

    @allure.title("Получение пользователя по id")
    def test_get_user(self, users_client: UsersClient):
        with allure.step("Запрашиваем пользователя с id=1"):
            user = users_client.get_user(user_id=1)

        with allure.step("Проверяем, что данные пользователя корректны"):
            assert user.id == 1
            assert "@" in user.email
```

Если упадёт второй `assert`, в отчёте будет видно: шаг "Запрашиваем пользователя..." — зелёный, шаг "Проверяем, что данные..." — красный, и именно в нём — traceback. Не нужно перечитывать весь тест, чтобы понять, где именно сломалось.

Обрати внимание на связку `@allure.epic` + `@allure.feature` на уровне класса — это распространяется на все тесты внутри `TestUsers`, повторять на каждом методе не нужно.

## Частые ошибки

- Слишком мелкая разбивка на шаги (`allure.step` на каждую строчку) — отчёт превращается в такой же шум, каким был voir код без разметки. Шаг — это осмысленный кусок сценария ("открыли форму", "заполнили и отправили", "проверили результат"), а не техническая мелочь.
- `allure.title` дублирует то, что и так понятно из имени функции — тогда декоратор не добавляет пользы. Хорошее название описывает бизнес-сценарий, а не техническую механику.
- Забыть, что `allure.step` — это context manager (`with allure.step(...):"`), а не декоратор — синтаксис у него другой, чем у `allure.title`.

## Мини-задание

Возьми любой свой тест из модуля 3 или 4 (API или UI) и добавь в него `@allure.title` с человекочитаемым названием и минимум два `allure.step` — один на подготовку/действие, один на проверку.
