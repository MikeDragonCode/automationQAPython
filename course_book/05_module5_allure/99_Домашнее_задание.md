# Домашнее задание модуля 5

## Что нужно сделать

Возьми **все** свои тесты, которые уже есть в общем репозитории (из модулей 3 и 4 — API и UI), и приведи их к единому стандарту Allure-разметки:

1. На каждом тестовом классе — `@allure.epic(...)` и `@allure.feature(...)`.
2. На каждом тесте — `@allure.title(...)` с человекочитаемым названием сценария (не техническое имя функции).
3. Внутри каждого теста — минимум 2 `allure.step`: один на подготовку/действие, один на проверку. Для более сложных сценариев (например, полная регистрация) — 3-4 шага, по одному на логичный этап сценария.
4. Убедиться, что UI-тесты используют фикстуру `page` в цепочке зависимостей (через `registration_page`/`dashboard_page` или напрямую) — тогда автоматическое приложение скриншота при падении из `conftest.py` сработает без дополнительного кода.

## Критерии "готово"

- `pytest --alluredir=allure-results` отрабатывает без ошибок.
- В сгенерированном отчёте (`allure serve allure-results`) видно дерево `epic -> feature -> тест` без "безымянных" узлов.
- В отчёте у каждого теста есть минимум 2 шага.
- Специально сломанный (временно) UI-тест показывает приложенный скриншот.
- Изменения оформлены как PR в общий репозиторий (по правилам модуля 2), ревью — от одногруппника.

## Что не нужно делать

- Не нужно настраивать публикацию отчёта на внешнем сервисе (Allure TestOps и подобные) — это вне программы курса.
- Не нужно приклеивать скриншоты вручную в каждом тесте — это уже сделано один раз в `conftest.py`.
