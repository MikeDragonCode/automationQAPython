# Домашнее задание: Модуль 1 — pytest как среда

## Формулировка задания

Напишите **10–15 тестов** на простых Python-утилитах, используя всё, что вы прошли в модуле 1: фикстуры, параметризацию, маркеры, `conftest.py`, `pytest.raises` и сравнение сложных структур.

Материал для тестирования на выбор (можно совмещать):

* функции из `boilerplate/utils/string_utils.py` — `is_palindrome`, `slugify`, `chunk_list`, `count_vowels` (файл только читаем, не изменяйте его — тесты пишутся в вашем собственном учебном проекте, а не в `boilerplate`);
* 2–3 своих новых чистых функции без внешних зависимостей (без сети, без файлов, без браузера) — например, функция подсчёта уникальных слов в строке, функция валидации email по простому шаблону, функция округления числа до ближайшего кратного и т. п.

Это модуль 0–1 курса: домашнее задание сдаётся **файлами** (архив или ссылка на ваш личный репозиторий), а не PR-ом — PR-флоу в общий репозиторий `boilerplate` начнётся в модуле 2.

## Ожидаемая структура проекта

```
homework_module1/
├── pytest.ini
├── conftest.py
├── utils/
│   └── ...            # ваши функции или скопированные string_utils.py
└── tests/
    ├── test_....py
    └── test_....py     # минимум 2 тестовых файла, чтобы conftest.py был реально нужен
```

## Критерии «готово»

Задание засчитывается, если выполнено **всё** нижеперечисленное:

- [ ] Не менее **10 тестовых функций** (`def test_...`) в сумме по всем файлам; допускается, что часть из них параметризована несколькими наборами данных.
- [ ] Использован хотя бы один **`@pytest.mark.parametrize`** минимум с 3 наборами данных.
- [ ] На тестах расставлены **маркеры** (например, `unit`), и все использованные маркеры **зарегистрированы** в `pytest.ini`.
- [ ] В `pytest.ini` включён **`--strict-markers`** (через `addopts`), и запуск `python -m pytest` проходит без ошибок о незарегистрированных маркерах.
- [ ] Указан **`testpaths = tests`** (или аналогичная настройка), команда `python -m pytest` из корня проекта находит все тесты без явного указания пути.
- [ ] Есть минимум **одна фикстура с областью видимости, отличной от `function`** (`class` или `session`) — и рядом с ней комментарий на 1–2 строки, почему выбран именно такой scope и почему это безопасно (то есть тест не мутирует расшаренные данные).
- [ ] Есть минимум **одна цепочка зависимых фикстур** (одна фикстура запрашивает другую).
- [ ] Есть **`conftest.py`**, и хотя бы одна фикстура из него используется минимум в двух разных тестовых файлах без единого `import`.
- [ ] Есть минимум **один тест на `pytest.raises`** — на исключение, которое ваш код (или `chunk_list`) действительно поднимает при некорректном вводе.
- [ ] Есть минимум **один тест, сравнивающий сложную структуру** (список списков, список словарей или словарь) через `==`.
- [ ] Все тесты **проходят** при запуске `python -m pytest -v` без ошибок и без предупреждений о маркерах.

## Как сдавать

Пришлите архив проекта (или ссылку на публичный репозиторий/gist) с указанной структурой. В сопроводительном сообщении укажите команду, которой вы проверяли, что все тесты проходят (обычно это `python -m pytest -v`), и её итоговый вывод (сколько тестов собрано и сколько прошло).
