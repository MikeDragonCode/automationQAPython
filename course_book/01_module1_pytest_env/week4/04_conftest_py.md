# 1.10. conftest.py: общие фикстуры для нескольких файлов

## Зачем это нужно

Как только фикстура нужна больше чем одному тестовому файлу, копировать её в каждый файл — плохая идея: любое изменение придётся синхронизировать вручную во всех копиях. В `boilerplate` уже есть готовый пример такого файла — `boilerplate/conftest.py`, в котором лежат фикстуры для UI-тестов, API-клиента и даже хук для скриншотов при падении. Разобраться, как он работает, важно ещё до того, как вы начнёте его дополнять в следующих модулях.

## Теория

`conftest.py` — специальное имя файла, которое pytest распознаёт автоматически. Фикстуры (и некоторые другие настройки, например хуки), определённые в нём, становятся доступны во всех тестовых файлах, которые находятся **в той же директории или ниже по дереву** — без единого `import`.

```
my_practice_project/
├── conftest.py                 # видно всем тестам ниже
└── tests/
    ├── test_string_utils.py
    └── test_more_utils.py
```

```python
# conftest.py
import pytest


@pytest.fixture
def sample_titles():
    return ["Hello World", "  Python  QA  ", "Already-Slug"]
```

```python
# tests/test_string_utils.py
from utils.string_utils import slugify


def test_slugify_uses_sample_titles(sample_titles):
    assert slugify(sample_titles[0]) == "hello-world"
```

Фикстура `sample_titles` доступна в `tests/test_string_utils.py`, хотя нигде не импортировалась — pytest сам читает `conftest.py` во время сбора тестов и регистрирует найденные в нём фикстуры.

### Область действия по расположению в дереве папок

`conftest.py` в корне проекта — общий для всех тестов проекта. Если положить дополнительный `conftest.py` внутрь конкретной поддиректории (например, `tests/unit/conftest.py`), его фикстуры будут доступны только тестам внутри `tests/unit/` и ниже, но не тестам в `tests/api/` или `tests/ui/`. Так можно разделять по-настоящему общие фикстуры (в корневом `conftest.py`) и специфичные для одного вида тестов (в локальном `conftest.py` нужной поддиректории).

### conftest.py — это не тестовый файл

`conftest.py` не должен содержать тестовые функции (`test_...`) — его роль другая: хранить общую подготовку (фикстуры, хуки), которую используют тесты из настоящих тестовых файлов. Также не стоит называть его с префиксом `test_` — иначе pytest попытается собрать его как обычный тестовый файл, что не является его назначением.

## Пример

Посмотрите на настоящий `boilerplate/conftest.py` — вот его ключевая часть:

```python
import pytest
from playwright.sync_api import Page

from clients.users.users_client import UsersClient, get_users_client


@pytest.fixture
def user_data() -> dict[str, str]:
    return {
        "email": get_random_email(),
        "username": get_random_username(),
        "password": get_random_password(),
    }


@pytest.fixture(scope="session")
def users_client() -> UsersClient:
    return get_users_client()
```

Это ровно та ситуация, которую мы разобрали в предыдущем уроке про `scope`: `user_data` создаётся заново на каждый тест (`scope` по умолчанию — `function`), потому что для разных тестов нужны разные, не пересекающиеся данные пользователя. А `users_client` объявлен с `scope="session"` — HTTP-клиент безопасно создать один раз и переиспользовать во всех тестах, которые к нему обращаются, без риска что-то сломать общей мутацией. Оба этих правила вы уже знаете — теперь видно, как они применяются в реальном, а не учебном коде.

Ни `user_data`, ни `users_client` нигде не импортируются в тестовых файлах модулей 3–4 — они просто указываются как параметры тестовых функций, точно так же, как в примере выше с `sample_titles`.

## Частые ошибки

* Пытаться сделать `from conftest import user_data` и вызвать фикстуру вручную (`data = user_data()`) — это ломает саму идею фикстур: пропадает и автоматическое разрешение зависимостей, и корректная работа `scope`. Фикстуру из `conftest.py` нужно использовать так же, как любую другую — указать её имя параметром теста, и всё.
* Положить `conftest.py` не в ту директорию, ожидая, что он будет виден «всему проекту» — файл действует только на директорию, в которой лежит, и на всё, что вложено ниже, но не «вбок» и не выше.
* Определить в двух разных `conftest.py` (корневом и вложенном) фикстуру с одинаковым именем и не глазами не заметить — вложенный `conftest.py` переопределяет фикстуру для тестов внутри своей директории, что иногда оказывается неожиданным поведением, если про это не помнить.
* Назвать файл `test_conftest.py` вместо `conftest.py` — pytest начнёт собирать его как тестовый файл, а фикстуры общими для других файлов не станут.

## Мини-задание

В своём учебном проекте создайте `conftest.py` в корне с одной-двумя фикстурами (например, `sample_titles` из примера выше) и минимум два тестовых файла, каждый из которых использует хотя бы одну из этих фикстур без единого импорта. Запустите `python -m pytest -v` и убедитесь, что оба файла успешно находят фикстуры.
