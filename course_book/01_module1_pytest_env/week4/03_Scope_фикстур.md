# 1.9. Scope фикстур: function, class, session

## Зачем это нужно

Позже в курсе вы будете создавать фикстуры для дорогих в подготовке ресурсов — HTTP-клиента, браузера, соединения с окружением. Пересоздавать их перед каждым тестом иногда расточительно по времени, но и делать «одну на всех» рискованно, если тест может случайно изменить то, что получил. `scope` — это именно тот рычаг, который управляет этим компромиссом, и его нужно понимать до того, как в фикстуре появится что-то дороже списка чисел.

## Теория

По умолчанию у фикстуры область видимости (`scope`) равна `"function"` — она создаётся заново для **каждого** теста, который её запрашивает, и после теста не переживает. Это самый безопасный вариант: тесты полностью изолированы друг от друга и не могут случайно повлиять друг на друга через общий объект.

pytest поддерживает несколько значений `scope`; в этом уроке — три самых важных для старта:

* **`function`** (по умолчанию) — новый экземпляр на каждый тест.
* **`class`** — один экземпляр на весь тестовый класс: все тестовые методы внутри одного `class Test...` получают один и тот же объект, а для другого класса будет создан новый.
* **`session`** — один экземпляр на весь запуск pytest целиком: все тесты во всех файлах получают ровно один и тот же объект.

Указывается scope так:

```python
@pytest.fixture(scope="session")
def something():
    ...
```

Существуют и более широкие/промежуточные scope (`module`, `package`), но для начала важнее твёрдо усвоить разницу между этими тремя.

### Главный компромисс: безопасность против переиспользования

Более широкий scope означает, что объект **переживает несколько тестов**. Если этот объект — изменяемый (список, словарь) и один тест его модифицирует, изменение «утечёт» в следующий тест, который получит тот же самый объект, а не свежую копию. Это классический источник тестов, которые проходят по отдельности, но падают в другом порядке или все вместе — потому что на самом деле они не независимы, а тайно делят состояние.

Общее правило: используйте `function`-scope по умолчанию для всего, что тест может изменить. Расширяйте scope только для того, что дорого создавать и что безопасно читать, не изменяя (например, клиент для HTTP-запросов, который не хранит изменяемое состояние теста).

> Забегая вперёд: именно поэтому в `boilerplate/conftest.py` фикстура `users_client` объявлена с `scope="session"` — создать HTTP-клиент один раз на весь прогон дёшево и безопасно, а вот `user_data` (данные конкретного пользователя, которые должны быть разными в разных тестах) оставлена с scope по умолчанию.

## Пример

### function против session: утечка изменений

```python
import pytest


@pytest.fixture(scope="function")
def function_scoped_words():
    return ["kayak", "hello"]


@pytest.fixture(scope="session")
def session_scoped_words():
    return ["kayak", "hello"]


def test_mutate_function_scoped(function_scoped_words):
    function_scoped_words.append("racecar")
    assert len(function_scoped_words) == 3


def test_function_scoped_is_fresh_again(function_scoped_words):
    # function-scope: для каждого теста — новый список
    assert function_scoped_words == ["kayak", "hello"]


def test_mutate_session_scoped(session_scoped_words):
    session_scoped_words.append("racecar")
    assert len(session_scoped_words) == 3


def test_session_scoped_keeps_the_mutation(session_scoped_words):
    # session-scope: это тот же самый объект, что и в предыдущем тесте!
    assert "racecar" in session_scoped_words
```

Второй тест из первой пары проходит именно потому, что `function_scoped_words` пересоздаётся заново. Второй тест из второй пары проходит по прямо противоположной причине — фикстура **не** пересоздаётся, и мутация из предыдущего теста никуда не делась.

### class: одна фикстура на весь класс

```python
import pytest


creation_log = []


@pytest.fixture(scope="class")
def big_dataset():
    creation_log.append("created")
    return list(range(1, 1001))


class TestChunkingOnBigDataset:
    def test_first_elements(self, big_dataset):
        assert big_dataset[:3] == [1, 2, 3]

    def test_dataset_length(self, big_dataset):
        assert len(big_dataset) == 1000
        assert len(creation_log) == 1  # фикстура создана один раз на весь класс
```

Оба метода внутри `TestChunkingOnBigDataset` получают один и тот же список — `creation_log` после выполнения обоих тестов содержит только одну запись, хотя фикстуру запросили дважды.

## Частые ошибки

* Не учитывать, что более широкий scope означает общий, а не заново созданный объект, и мутировать его в тесте — самая частая причина «тестов, которые ломаются только вместе, а по отдельности проходят».
* Ставить `scope="session"` «для скорости» там, где создание объекта и без того дешёвое (например, для короткого списка или словаря) — выигрыш по времени незаметен, а риск случайно расшарить состояние остаётся.
* Пытаться сделать fixture с `scope="session"`, которая при этом зависит от `function`-scoped фикстуры — pytest не позволит этого (`ScopeMismatch`), потому что fixture с более широкой областью видимости не может опираться на то, что живёт меньше, чем она сама.
* Путать `class`-scope с «на весь файл» — на самом деле область действия строго ограничена одним классом; тесты вне класса или в другом классе получат отдельный, новый экземпляр.

## Мини-задание

Напишите собственный пример с `scope="class"` и фикстурой, возвращающей словарь (например, `{"count": 0}`). В первом тестовом методе класса увеличьте значение `count` на единицу. Во втором методе того же класса проверьте (и заранее письменно предположите, до запуска), увидите вы там `0` или уже изменённое значение — а затем запустите тесты и сравните с предположением.
