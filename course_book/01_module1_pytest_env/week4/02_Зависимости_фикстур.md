# 1.8. Фикстуры, которые зависят друг от друга

## Зачем это нужно

Реальная подготовка окружения редко бывает одноуровневой. Например, в модуле 4 вы встретите фикстуру `registration_page(page: Page)` — она сама зависит от другой фикстуры, `page`, которую предоставляет `pytest-playwright`. pytest умеет строить и разрешать такие цепочки автоматически, и это одна из самых полезных возможностей фреймворка — если понимать, как она работает.

## Теория

Фикстура может запрашивать другую фикстуру точно так же, как это делает тест — просто указав её имя как свой параметр:

```python
@pytest.fixture
def registration_page(page: Page) -> RegistrationPage:
    return RegistrationPage(page)
```

Здесь `registration_page` зависит от `page`. Когда какой-то тест запрашивает `registration_page`, pytest сначала находит и вызывает `page`, передаёт её результат в `registration_page`, и только затем результат `registration_page` попадает в тест. Вся цепочка разрешается автоматически — вам не нужно вручную прописывать порядок вызова.

Цепочки могут быть длиннее одного уровня: фикстура A зависит от B, B зависит от C — pytest построит граф зависимостей и вызовет всё в правильном порядке, от «самой глубокой» зависимости к «самой верхней».

### Цепочка из трёх уровней на практике

Вот как это выглядит в коде, а не только в описании — три фикстуры, каждая следующая опирается на предыдущую:

```python
from utils.string_utils import is_palindrome


@pytest.fixture
def raw_words():
    return ["kayak", "Hello", "level"]


@pytest.fixture
def normalized_words(raw_words):
    return [word.lower() for word in raw_words]


@pytest.fixture
def palindrome_flags(normalized_words):
    return [is_palindrome(word) for word in normalized_words]


def test_palindrome_flags(palindrome_flags):
    assert palindrome_flags == [True, False, True]
```

Тест запрашивает только `palindrome_flags`, но чтобы её получить, pytest сначала вызовет `raw_words`, затем `normalized_words`, и только потом — саму `palindrome_flags`. Ни `raw_words`, ни `normalized_words` тест напрямую не упоминает — они нужны только как промежуточные звенья цепочки.

### Фикстура может зависеть сразу от нескольких фикстур

Зависимость не обязана быть «цепочкой из одного звена» — фикстура может запросить сразу несколько других фикстур как параметры, точно так же, как тест может запросить сразу несколько фикстур:

```python
@pytest.fixture
def report_prefix():
    return "QA-REPORT"


@pytest.fixture
def full_report(report_prefix, palindrome_flags):
    return f"{report_prefix}: {palindrome_flags}"


def test_full_report_contains_prefix(full_report):
    assert full_report.startswith("QA-REPORT")
```

Здесь `full_report` зависит сразу от двух фикстур: независимой `report_prefix` и уже знакомой цепочки `palindrome_flags` (которая, в свою очередь, зависит от `normalized_words` и `raw_words`). pytest одинаково легко строит и линейные цепочки, и такие «сходящиеся» графы, где у одной фикстуры несколько независимых источников данных.

### Важная деталь: кеширование в пределах одного теста

Если в одном тесте фикстура запрашивается сразу двумя способами — напрямую и через другую фикстуру, которая от неё зависит, — pytest вызовет эту фикстуру **только один раз** и переиспользует один и тот же результат в обоих местах. Это справедливо даже для фикстур с областью видимости по умолчанию (`function`, о которой пойдёт речь в следующем уроке): кеш действует не «на весь прогон», а «в пределах одного теста, который её запросил».

## Пример

Построим двухуровневую цепочку на функциях из `boilerplate/utils/string_utils.py`:

```python
import pytest

from utils.string_utils import slugify


@pytest.fixture
def raw_titles():
    return ["Hello World", "  Python  QA  ", "Already-Slug"]


@pytest.fixture
def slugified_titles(raw_titles):
    return [slugify(title) for title in raw_titles]


def test_slugified_titles_have_no_spaces(slugified_titles):
    assert all(" " not in title for title in slugified_titles)


def test_slugified_titles_count_matches_source(slugified_titles, raw_titles):
    assert len(slugified_titles) == len(raw_titles)
```

Во втором тесте запрошены сразу обе фикстуры — и `slugified_titles`, и `raw_titles`, от которой она зависит. Несмотря на это, `raw_titles` будет вызвана всего один раз за этот тест, а не дважды: один и тот же список `["Hello World", "  Python  QA  ", "Already-Slug"]` окажется и в переменной `raw_titles`, и внутри `slugified_titles`.

## Частые ошибки

* Строить циклическую зависимость (фикстура A запрашивает B, а B — снова A) — pytest не сможет разрешить такой граф и завершится ошибкой ещё на этапе сбора тестов.
* Делать цепочки из четырёх-пяти уровней «просто потому что можно» — чем длиннее цепочка, тем сложнее понять, что на самом деле получает тест и в каком порядке всё собирается; там, где хватает одного уровня, не стоит усложнять.
* Ожидать, что зависимая фикстура пересоздаст «родительскую» заново при повторном упоминании в том же тесте — как показано выше, в пределах одного теста результат кешируется и переиспользуется, а не вычисляется с нуля каждый раз.
* Давать фикстурам имена, которые случайно совпадают с локальными переменными или именами функций в том же файле — это не сломает код, но будет сбивать с толку при чтении.
