# 1.1. Что такое pytest и зачем он нужен

## Зачем это нужно

В любой вакансии QA Automation Engineer на Python встречается слово `pytest`. Это не совпадение: pytest — фактический стандарт для запуска тестов в Python-экосистеме, и дальше в этом курсе он будет использоваться в каждом модуле — для unit-тестов, API-тестов и UI-тестов на Playwright. Прежде чем усложнять тесты браузером или HTTP-запросами, важно понять, что вообще делает pytest и почему обычный Python-скрипт с проверками — это не то же самое, что автотест.

## Теория

До этого модуля вы писали Python-код, который выполняется сверху вниз: скрипт запускается, делает свою работу и завершается. Если внутри есть `assert`, программа просто упадёт с ошибкой при первом же нарушении условия — и на этом всё.

Такой подход работает, пока в проекте одна проверка. Но что происходит, когда проверок становится десять, пятьдесят, сто? Возникают вопросы:

* Какие проверки нужно запустить — все или только часть?
* Какие из них прошли успешно, а какие нет?
* Если проверка не прошла — где именно и почему?
* Как запустить только「быстрые」тесты, а не все сразу?

Обычный скрипт не даёт ответов на эти вопросы «из коробки». Именно для этого существуют тестовые фреймворки, и pytest — самый популярный из них для Python.

**pytest не выполняет действия за вас** (не открывает браузер, не делает HTTP-запросы) — это делают другие библиотеки (Playwright, requests). Задача pytest — организовывать, находить, запускать тесты и красиво показывать результат.

Коротко: если ваш код выполняет действия — это делает *другая* библиотека. Если код проверяет, что действия дали ожидаемый результат, и pytest управляет тем, как и когда это проверяется — это тест.

### Установка и запуск

pytest устанавливается как обычный пакет:

```bash
pip install pytest
```

В `boilerplate/requirements.txt` пакет уже указан — при установке зависимостей проекта pytest ставится автоматически.

Запустить тесты можно двумя способами:

```bash
pytest
```

```bash
python -m pytest
```

Разница на первый взгляд незаметна, но важна: `python -m pytest` добавляет текущую директорию в `sys.path`, поэтому импорты вида `from utils.string_utils import slugify` работают надёжнее независимо от того, откуда именно вы запускаете команду. В этом курсе везде используется именно `python -m pytest`.

После запуска pytest самостоятельно найдёт тестовые файлы и функции (как именно — тема следующего урока), выполнит каждую как отдельный, независимый друг от друга тест и покажет итоговую статистику: сколько тестов прошло, сколько упало и где именно.

## Пример

В `boilerplate` уже есть готовый пример — файл `boilerplate/tests/unit/test_string_utils.py`, который тестирует функции из `boilerplate/utils/string_utils.py` (`is_palindrome`, `slugify`, `chunk_list`, `count_vowels`). Запустите его в подробном режиме:

```bash
python -m pytest tests/unit/test_string_utils.py -v
```

Вывод будет примерно таким:

```
======================== test session starts ========================
collected 11 items

tests/unit/test_string_utils.py::test_is_palindrome[racecar-True] PASSED
tests/unit/test_string_utils.py::test_is_palindrome[A man a plan a canal Panama-True] PASSED
tests/unit/test_string_utils.py::test_is_palindrome[hello-False] PASSED
tests/unit/test_string_utils.py::test_is_palindrome[-True] PASSED
tests/unit/test_string_utils.py::test_slugify[Hello World-hello-world] PASSED
...
tests/unit/test_string_utils.py::test_count_vowels_counts_ru_and_en PASSED

========================= 11 passed in 0.02s =========================
```

pytest сам нашёл файл, нашёл все тестовые функции внутри него (включая параметризованные варианты — про них будет отдельный урок), выполнил их и посчитал итог. Ничего из этого не пришлось писать руками.

Для сравнения попробуйте запустить тот же файл как обычный Python-скрипт:

```bash
python tests/unit/test_string_utils.py
```

Ничего не произойдёт — файл просто отработает и завершится без вывода, потому что в нём нет кода, который вызывает тестовые функции напрямую. Тестовые функции существуют только для того, чтобы их находил и запускал pytest.

## Частые ошибки

* Пытаться запустить тестовый файл как обычный скрипт (`python test_file.py`) и удивляться, что «ничего не происходит» — тестовые функции просто не вызываются сами по себе.
* Забыть установить pytest или активировать виртуальное окружение проекта перед запуском — команда `pytest` не найдётся или тесты будут использовать не те версии зависимостей.
* Добавлять в тестовый файл блок `if __name__ == "__main__":`, пытаясь «запускать тест как скрипт» — это не нужно и не является тем, как принято работать с pytest.
* Путать pytest с `unittest` (встроенным в Python модулем тестирования) — в pytest тесты пишутся как обычные функции с обычным `assert`, без классов `TestCase` и методов `self.assertEqual(...)`.

## Мини-задание

1. Убедитесь, что pytest установлен: `pip show pytest`.
2. Запустите `python -m pytest tests/unit/test_string_utils.py -v` в `boilerplate` и посчитайте: сколько тестов было собрано (`collected`) и сколько прошло (`passed`).
3. Попробуйте запустить этот же файл напрямую через `python tests/unit/test_string_utils.py` и в одном предложении объясните, почему ничего не произошло.
