# RU. Резюме junior QA automation engineer

## Зачем это нужно

Резюме — это фильтр до собеседования. У рекрутера обычно 20-30 секунд на первый просмотр; резюме без конкретики про автоматизацию ("занимался тестированием", "изучал Python") отсеивается раньше, чем кто-то дочитает до опыта.

## Структура резюме под этот курс

1. **Заголовок и позиция.** "QA Automation Engineer (Junior)" — конкретно, не "тестировщик" общим словом, если цель именно автоматизация.
2. **Стек технологий.** Список без воды: Python, pytest, requests, Pydantic, Playwright, Allure, Git, базовое понимание CI (GitHub Actions/GitLab CI). Пиши только то, чем реально пользовался в курсе — на собеседовании про каждый пункт могут спросить.
3. **Проект/опыт.** Вместо "проходил курс по автоматизации тестирования" — конкретно: "Разработал и поддерживал автотесты (API + UI) в командном репозитории на Python/pytest/Playwright, участвовал в code review, настраивал allure-отчётность". Это честное описание того, что реально происходило в модулях 2-7.
4. **Ссылка на GitHub.** Обязательно — ссылка на общий репозиторий курса (или свой форк) с историей PR. Это ЕДИНСТВЕННОЕ, что реально доказывает навыки джуниору без коммерческого опыта — работодатель может открыть и увидеть реальный код, реальные PR, реальные ревью.
5. **Образование/курсы.** Кратко, в конце. Название курса, продолжительность — не расписывай подробно программу, это не главное.

## Частые ошибки

- Резюме на 2-3 страницы для позиции junior — эйчар не читает длинные резюме от кандидатов без опыта, максимум одна страница.
- Перечисление технологий, которых не было в реальной практике курса ("Selenium, TestNG, Java") "для солидности" — на собеседовании это быстро вскрывается и работает против кандидата.
- Отсутствие ссылки на GitHub — для automation-инженера без коммерческого опыта это самый весомый аргумент, отсутствие ссылки выглядит как нежелание показать код.
- Общие фразы без цифр/фактов: "ответственный, обучаемый, коммуникабельный" — для технической позиции это не то, что решает.

## Мини-задание

Напиши раздел "Опыт/проект" своего резюме, опираясь на реальные PR из общего репозитория курса — минимум 3 конкретных пункта (например: "Реализовал API-клиент для работы с /users, покрыл 5 тестами позитивные и негативные сценарии", "Настроил автоматическое приложение скриншотов в Allure при падении UI-тестов").
