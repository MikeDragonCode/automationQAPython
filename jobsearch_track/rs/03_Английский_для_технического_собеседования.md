# RS. Английский для технического собеседования

## Зачем это нужно

Технические термины (fixture, assert, locator, pipeline) большинство студентов уже используют по-английски (см. `STYLE_GUIDE.md` всего курса) — но объяснить свой код и опыт связной английской речью на интервью значительно сложнее, чем понимать документацию.

## На чём фокусироваться

Технический английский для собеседования — это не грамматика уровня экзамена, а свободное владение конкретным ограниченным набором конструкций:

1. **Объяснение решения задним числом.** "I implemented a `UsersClient` that inherits from a base `APIClient`, because it lets us reuse the same GET/POST/PATCH/DELETE logic across all API clients." — конструкция "I did X, because Y" покрывает большую часть ответов на технические вопросы.
2. **Описание проблемы и её решения.** "The test was flaky because the assertion ran before the page finished loading, so I replaced it with an explicit `expect()` wait." — эта же конструкция из модуля 7 (багфиксы), но на английском.
3. **Уточняющие вопросы.** "Could you clarify what environment this would run in?", "Do you mean the request body or the response?" — уметь переспрашивать важнее, чем бояться показаться не понявшим с первого раза.
4. **Мышление вслух.** На многих live-coding интервью ожидают, что кандидат объясняет ход мыслей в процессе, а не молча пишет код и объясняет в конце. Фразы вроде "Let me think about edge cases here" помогают держать разговор, пока формулируется решение.

## Как готовиться, используя материал курса

- Пройдись по своим PR из модуля 7 и опиши на английском вслух (или письменно) каждый: что за проблема, как её нашёл, как исправил — это прямая тренировка структуры "I did X because Y".
- Прогони mock-интервью с одногруппником полностью на английском по чек-листу тем из `ru/03_Подготовка_к_собеседованию.md` (темы те же, язык другой).
- Запиши себя на видео/аудио, отвечая на 2-3 типовых вопроса — часто ошибки слышны самому при пересмотре лучше, чем в моменте разговора.

## Частые ошибки

- Учить фразы, не связанные с реальным опытом — заученный ответ "расскажи о своём проекте" звучит неестественно без конкретики из собственных PR.
- Молчать при незнакомом слове/термине вместо того, чтобы переспросить — на реальном собеседовании переспросить нормально, тишина работает против кандидата сильнее.
- Готовиться только к вопросам "расскажи о себе", игнорируя техническую лексику по конкретным темам курса (pytest, Git, API, Playwright) — именно там будут специфичные термины, которые не всплывают в бытовом английском.

## Мини-задание

Запиши голосовую заметку (2-3 минуты) с ответом на вопрос "Tell me about a bug you found and fixed in a teammate's test" на английском, опираясь на реальный PR из модуля 7. Прослушай сам и отметь, какие фразы дались тяжелее всего.
